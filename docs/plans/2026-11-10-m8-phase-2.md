# Phase 2 (roadmap M8) — implementation plan

## Context
Phase 1 (MVP) is merged to `main`. Phase 2 adds five things, defined in `docs/plans/2026-11-10-phase-2-handoff.md` and the spec's "Phase 2 screens": dictionary phrase detection, sentence history (past occurrences of unsaved words), fullscreen, the "Words in this video" tab, and a Spanish → English pack. Screens follow the approved mock artboards `VideoWords.dc.html`, `Fullscreen.dc.html`, `PastOccurrences.dc.html`.

Decisions taken with the user (2026-11-10):
- Video sentence history keeps **played lines only** (same rule as encounters)
- Words tab **leaves out words known only by the frequency level**; the Known chip counts saved Known terms
- Phrase meaning order: **EJDict → Wiktionary Japanese translation → Wiktionary English definition**; the built-in translator only for selected phrases found in no dictionary

## How it runs
- Branch `feat/phase-2` from `main`, one PR. Per milestone a short plan in `docs/plans/2026-11-10-m8x-*.md` (format of the M7 plan), then superpowers:subagent-driven-development, TDD, English in the repo, no Claude attribution, commit per task
- Order: **A phrases → B Spanish → C sentence history → D words tab → E fullscreen** (A before C because history indexes phrase keys; A before D because the tab lists detected phrases)
- End of each milestone: `npm run check`, `npm test`, `VITEST_BROWSERS=chromium npm run test:browser`, `npm run build` + `build:firefox`, `npm run test:e2e:build`
- UI milestones: screenshot pairs (real UI vs mock) before committing; mock comment threads, mock and spec updated if anything changes

## A. Dictionary phrase detection
- **Data** (`scripts/data/kaikki.mjs`, new `phrases.mjs` or an extension of it): from `kaikki-en.jsonl` take multi-word entries whose words are all in the vocabulary and that are idioms / phrasal verbs / prepositional phrases (sense tags `idiomatic`, categories "phrasal verbs", pos `phrase`/`prep_phrase`/multi-word `verb`), merged with EJDict's 4,434 multi-word headwords. Outputs:
  - `en/phrases.json`: phrase keys as sequences of base forms (same key rule as saved phrases in `src/core/term-id.ts` / classifier)
  - `en/defs-<n>.json` + index: English definitions (first glosses per sense, with pos) for phrases; sharded via the existing `shardDict` pattern
  - `en-ja/phrase-ja.json`: kaikki `translations[]` with `lang_code: "ja"` for phrases EJDict lacks
  - Measure count and sizes; each file < 4 MB (`pack-sizes.test.ts` covers new files automatically); record in `docs/status.md`
- **Pack/dictionary** (`src/core/language-pack.ts`, `src/core/dictionary.ts`, `src/core/packs/load.ts`): `LanguagePack.phrases` (set of keys); `createEnJaDictionary` falls back EJDict → `phrase-ja` → English definitions, sets `glossLang` on the entry/senses, and always returns IPA via `ipaFor` (fixes the missing phrase IPA even without an entry)
- **Classifier** (`src/core/classify.ts`): `phraseIndexOf` merges pack phrases with saved ones (saved win, longest match unchanged); unsaved detected phrases get category `new` (the frequency level does not apply to phrases)
- **UI** (`src/ui/lookup/HoverCard.tsx`, `DictionaryWindow.tsx`, `src/content/article/describe.ts`): `lang` attribute from `glossLang` (English definitions tagged `en`); `describeTerm` uses the translator only when the dictionary has nothing; word list `listTermsWithStats` shows phrase meanings
- Tests: data fixtures (give up, from scratch, figure out), real-file smoke test, classifier phrase tests, DictionaryWindow `lang` test; E2E: an article fixture phrase is highlighted as New and opens with an English definition

## B. Spanish → English pack
- **Registry**: `src/background/language-resources.ts` gets a registry keyed by learning language and by `from-to` (`en`, `en-ja`, `es`, `es-en`); `PackFiles`/`LOADERS` in `load.ts` extended. en→ja factories and files stay unchanged (a test asserts en/en-ja outputs are byte-identical after the es build)
- **Data** (`scripts/data/` es variants, `npm run data:es`): vocabulary = lemmas of the top 30–50k forms of Wiktionary "Frequency lists/Spanish/Mixed 730K" that have kaikki entries with glosses; lemmas from `form_of` senses and filtered `forms` (drop `no-table-tags`, `es-conj`, clitic combos); IPA (first phonemic); pos per entry; `es-en` dictionary `{word: [short, senses with pos]}` from kaikki English glosses (pos labels come straight from kaikki, no gloss-ending guessing); Spanish multi-word entries as `es/phrases.json` if the size allows. Each file < 4 MB; total zipped size compared with phase 1's ~3 MB
- **Pack/dictionary**: `createSpanishPack` reuses `lemmatize`/`rankOf`/`ipaFor` (no English `'s` rule); `createEsEnDictionary`
- **Settings** (`SettingsPage.tsx`, `en.json`): learning select English / Spanish; native select lists only languages with a dictionary for the chosen learning language (en → Japanese, es → English), switching learning picks the first; `language.es`; slider copy already interpolates the language name
- **Other tables**: `SPEECH_LANG` (article, session, word list) gains `es: "es-ES"`; `externalDictionaries.ts` gets es-en links (Cambridge spanish-english, WordReference `esen`, Reverso, Wiktionary)
- Tests: data fixtures (comiendo → comer, casas → casa), registry tests, settings page select behavior, E2E with a Spanish article fixture

## C. Sentence history (past occurrences)
- **DB** (`src/background/db.ts`): Dexie `version(2)` adds `historyPages {id, platform, url, title, lang, firstSeen, lastSeen, bytes}` and `historySentences {++id, pageId, &[pageId+text], *keys, text, translation?, pos, seenAt}`; `meta` gains `historyBytes`. History is device-only: not synced, not in `exportJson`
- **Store** (new `src/background/history-store.ts`, tested like `term-store.browser.test.ts`): `record(source, items)` idempotent on `[pageId+text]`; running byte estimate; eviction of the oldest pages (by `lastSeen`) when over 50 MB; `find(termId, excludeUrl)` newest first, max 50; `status()` → bytes, cap, page count; `clear()`; `forgetHost(host)`
- **Capture**: new message `recordHistory {source, items: [{text, translation?, pos, keys}]}` (repeatable). Articles: sentences of analyzed blocks (`sentenceAt` moves to `src/core/text/`); videos: played cards only, in `played(w, i)` next to `recordEncounters`. Keys = termIds of non-ignored spans (words and phrases), leaving out the most frequent words (threshold set in the milestone plan after measuring). Background drops the request when `settings.sentenceHistory` is off or the sender's host is blocked (`hostBlocked`); adding a host to "Never run on" calls `forgetHost`
- **Lookup** (`handlers.ts`): for unsaved terms `elsewhere` comes from history; `ArticleUi.tsx`/`VideoUi.tsx` stop forcing `null` for New; `dict.notSavedNote` shown only when there is no history
- **Save import** (`term-store.ts saveTerm`): when a term becomes live, copy its history sentences into occurrences (`origin: "encountered"`, sources upserted), within `MAX_OCCURRENCES`
- **Settings page**: new `history` section per mock (copy, switch, "N MB of 50 MB" bar, "N pages and videos · …" / "Nothing kept yet", Clear); messages `historyStatus`, `clearHistory`; MB formatter in `src/ui/format/format.ts`
- **Store listing**: update `docs/status.md` "Before publishing" (justification: subtitles of played lines and page sentences are kept on the device when Sentence history is on; describe the feature in the listing)

## D. Words in this video
- `TranscriptUi` header: L badge + Transcript / Words tablist (mock); the Transcript tab keeps its phase-1 controls; Words tab shows filter chips All / New / Learning / Known with counts and the rows
- Rows built in the content side from `state.cues` + `visibleSpans` in order of first appearance, grouped by key+kind, count `N×`, highlight style from `src/ui/video/terms.tsx`; level-known unsaved words excluded
- Short meanings via a new batch message `shorts {lang, keys}` → `{short, glossLang}` per key (uses `dictionary.short`)
- Selecting a row calls `app.clickWord(firstRef)` (dictionary window with "In this video"); rows update live through `recategorize`
- Tests: Transcript/Words component Browser Mode tests, session test for row building, E2E on the YouTube fixture

## E. Fullscreen
- `mount.tsx`: the `lingo-video` host (dictionary window, hover card, end card) goes into `document.fullscreenElement ?? document.body` (not a `<video>`), `schedule()` on `fullscreenchange`
- `session.ts`: site captions stay hidden in fullscreen; `InPlayerUi` shows the subtitle in fullscreen with a larger `LOOK.fullscreen` (mock: 34 px / 24 px, wider box); `BelowVideoUi`/transcript hidden; `LingoMenu` gets a prop that drops the position section
- `placement.ts dictionaryFrame`: fullscreen branch (right 32, top 32, 360×420 per mock)
- Tests: mount/session Browser Mode tests (existing "follows fullscreen" tests change), E2E calling `requestFullscreen()` from a user gesture on both fixtures
