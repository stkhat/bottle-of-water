# Lingo phase 1 + phase 2 — implementation roadmap

## Context
Build Lingo through phase 2 following the [design spec](../specs/2026-11-08-language-learning-extension-design.md). **Tatoeba example sentences and Anki/CSV export are moved to phase 3.**

Decisions (2026-11-09)
- Phase-2 language pack: **Spanish → English** (kaikki Spanish data)
- Screens without a mock (word list page, per-video word list tab, fullscreen, past-occurrence search): **add them to the mock first; build those screens after the user reviews them**. Everything else proceeds without waiting
- git: **one branch and PR per stage** (`chore/dev-env` → `feat/phase-1` → `feat/phase-2`), committing per tested step and pushing. The user merges
- Execution: one subagent per task (superpowers:subagent-driven-development), with the controller reviewing each diff and test run

This document fixes only the order and cross-cutting rules. At the start of each milestone, a detailed plan (TDD steps with code) is written to `docs/plans/2026-11-xx-<name>.md`.

## Cross-cutting rules
- **Where data lives**: a content script's IndexedDB belongs to the page origin, so `TermStore` (Dexie), `LanguagePack` and `DictionaryProvider` live in the **background**. Content scripts and extension pages query it through typed messages (`src/messaging/`). Classification sends the page's list of base forms in one batch
- Pack data is bundled and read by the background via `runtime.getURL` (not `web_accessible_resources`), in compact formats (sorted arrays + binary search, etc.) so a restarted service worker reloads fast
- Extension APIs only via `wxt/browser`. Strings via `t("key")`, browser names via `BrowserEnv`. Branch on feature detection
- Three test layers from the dev-environment plan (Vitest Node / Vitest Browser Mode on Chromium and Firefox / Playwright E2E). See a test fail before implementing. Subtitles are tested with fixtures
- UI layout, copy, colors and defaults follow the mock's `.dc.html` files (re-read each time). Nothing that is not in the mock is added
- **Before committing a UI change, render it and compare with the mock**

## External data
See the spec's "Data sources". Raw downloads go to `data/raw/` (git-ignored); processed files go to `src/assets/packs/<lang>/`.

## Milestones

### M0. Spec and mock updates (committed first on `chore/dev-env`)
- Spec and CLAUDE.md in English; phase changes; data sources; `docs/status.md`
- Add mock artboards: ① word list page ② per-video word list tab ③ fullscreen ④ past-occurrence search (showing "Seen elsewhere" for unsaved words). Reuse the existing palette and parts; no extra help text or frames. Mirror them in the spec's "UI spec (follows the mock)"
- Ask the user to review and continue to M1 without waiting

### M1. Dev environment (`chore/dev-env`)
Execute [2026-11-09-dev-environment.md](2026-11-09-dev-environment.md) as written. Open a PR and fix until CI is green. `feat/phase-1` branches from here (no need to wait for the merge)

### M2. Data import (`feat/phase-1`)
- `scripts/data/ejdict.mjs`: headwords (expanding comma-separated variants) → translations; short translation (first sense) and meanings grouped from the notation (`/`, `;`, 〈C〉 …)
- `scripts/data/kaikki.mjs`: stream the JSONL; inflection → base form from `forms`, US IPA from `sounds`, multi-word headwords as phrase candidates
- `scripts/data/frequency.mjs`: frequency rank
- Build the output format together with its reader (`src/core/packs/`). Test ferments → ferment, loaves → loaf, IPA presence. Measure IPA coverage (share of the top 20,000 words) and record it in `docs/status.md`

### M3. Foundation (`feat/phase-1`)
- `LanguagePack` (en): segmentation with `Intl.Segmenter`, base forms, frequency rank, IPA (phrases join their words' IPA)
- `DictionaryProvider` (en→ja): short translation, meanings by part of speech
- `Classifier`: New / Learning / Known / ignored, saved-phrase matching, counting unsaved words on a page
- `TermStore`: Dexie `terms` / `sources` / `occurrences`, mandatory source, automatic re-occurrence recording (dedupe, 50 per word), `bulk` + Undo, JSON Export/Import (stores the last export time)
- `SyncBackend` / `BrowserSyncBackend`: status code + base36 minutes, gzip + base64, ~7 KB chunks, `QUOTA_BYTES`, tombstones and per-word timestamp merge, `storage.onChanged`, demoting `bulk` words near the limit. Measure how many words fit after compression with real data
- `BrowserEnv`, settings (`storage.sync`, defaults from the spec and mock), `t()`, background message handling

### M4. Shared UI parts `LookupUI` (`feat/phase-1`, tested in Browser Mode)
Hover card, dictionary window (drag, ×, `speechSynthesis`, four external dictionaries, In this video / On this page, Seen elsewhere), phrase-saving bar, save-all card ((i) explanation, count and Undo). Inside Shadow DOM. Brighter colors for dark video backgrounds

### M5. Article UI (`feat/phase-1`)
Page language (`<html lang>` → `i18n.detectLanguage`), CSS Custom Highlight API (background colors only when underlines are unsupported, detected in `BrowserEnv`), visible-range processing with MutationObserver, hover via `caretPositionFromPoint`, selection snapped to word boundaries, top-right card, end-of-article IntersectionObserver and "You reached the end" card, occurrence recording. Translation via the Translator API (if it is unavailable in content scripts, use an offscreen document — check first). E2E on a local test article

### M6. Video UI (`feat/phase-1`)
- `PlatformAdapter`: YouTube (MAIN-world fetch/XHR hook for `/api/timedtext` json3, try the Japanese track and `tlang=ja`, SPA navigation), Netflix (`JSON.parse` hook → manifest → TTML/WebVTT, seek through the player API)
- Choosing a translation (one per video, transcript assignment by time overlap)
- Two-column layout, transcript (emphasis, auto-scroll, click to seek, highlight toggles, translation switch), subtitle position (In video / Below video), green-outlined L button and ^ menu in the player bar, `requestVideoFrameCallback` + binary search, "Video finished" card on `ended`
- Parsing and assignment with Vitest fixtures. Screens with a local `<video>` test page in Browser Mode / E2E. Finally check real YouTube in Playwright Chromium with the extension. Netflix needs a login, so the user checks it manually

### M7. Popup, settings page, word list page (`feat/phase-1`)
Popup and settings as in the mock (last saved time and usage, "Saved to {syncName}", Coming later items, Never run on). **The word list page is built after the M0 mock review**; if no review has arrived, stop and ask. Then open the `feat/phase-1` PR and get CI green

### M8. Phase 2 (`feat/phase-2`, branched from `feat/phase-1`)
1. Automatic detection of dictionary phrases (phrase list from EJDict and kaikki multi-word headwords; saved phrases win)
2. Past-occurrence search: keep sentences from pages/videos opened with the extension on as a local corpus (base-form index, size cap, oldest evicted first). Show past occurrences even for unsaved words and import them into occurrences when the word is saved
3. Fullscreen support (subtitles, dictionary window and hover work in YouTube/Netflix fullscreen)
4. Per-video word list tab (next to the transcript)
5. Spanish → English pack (`LanguagePack` es, `DictionaryProvider` es→en, language choices in settings, language name in the frequency slider copy). Confirm it is added without touching the en→ja code
- Screens for 2–4 are built after the M0 mock review (1 and 5 go first). Then open the PR and get CI green
