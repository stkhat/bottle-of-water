# M4 — Shared lookup UI parts (`LookupUI`)

> Executed with superpowers:subagent-driven-development. TDD in Vitest Browser Mode (real Chromium/Firefox). Before committing, render each part and compare it with the mock.

**Goal:** the Preact components the article UI (M5) and the video UI (M6) share, matching the mock exactly: hover card, dictionary window, phrase-saving bar, and the save-all section/card. Pure presentation: data in through props, actions out through callbacks. No messaging, storage or page logic here (M5/M6 wire them).

**Mock sources (canonical):** `project/Main.dc.html` (hover `.pop` card, dictionary window `aside[aria-label="Dictionary window"]`, "Video finished" card), `project/Article.dc.html` (dictionary panel, phrase bar "Save “rise and fall” as a phrase", "You reached the end" card), `project/Toolbar.dc.html` ("This page" section). Inline styles and the `<helmet>` classes (`.pop`, `.pk`, `.ps`, `.ph`, `.pi`, `.pj`, `.pd`, `.pu`, `.pr`, `.pt`, `.sh`, `.ib`) are the source of truth for sizes, colors, fonts and copy.

## Components (`src/ui/lookup/`)
| File | Props (summary) | Notes |
|---|---|---|
| `HoverCard.tsx` | `{ kind: "word" \| "phrase", status: "learning" \| "known" \| "new", head, ipa?, short?, sub?, onLearning, onKnown }` | Mock `.pop`: kind label (WORD / PHRASE), status label (Learning / Known / "New · not saved"), head, IPA (hidden when missing), short translation (`lang` = native language), divider + `sub` only when present, "+ Learning" / "Known" buttons with the selected-state styles, "Click the word for details". Positioning is the caller's job (the component renders the box only) |
| `DictionaryWindow.tsx` | `{ variant: "window" \| "panel", entry: { head, kind, ipa?, sub?, short?, senses: {pos?, text}[] }, status, onStatus(s), onSpeak, dictionaries: {label, href}[], here: { title: "In this video" \| "On this page", items: { time?, text, onClick? }[] }, elsewhere: { title, meta, text, href, video: boolean }[] \| null, onClose, onDragStart?(e) }` | `window` = Main's floating window with the drag handle ("Move window") and header bar; `panel` = Article's right-side panel. Status buttons Learning / Known / Remove ("Not saved" when new). Meanings list (pos label only when present). "Dictionaries" links open in a new tab (`rel="noopener"`). "Seen elsewhere · N": when `elsewhere` is null (unsaved) show "Not saved yet. Save it as Learning or Known and Lingo will remember where you see it next." Missing sections (no senses, no dictionaries) are omitted, not shown empty |
| `useDrag.ts` | hook: pointer-drag a fixed-position element by a handle, clamped to the viewport | used by the window variant |
| `PhraseBar.tsx` | `{ text, onLearning, onKnown }` | Article's dark bar: `Save “{text}” as a phrase` + "+ Learning" + "Known" |
| `SaveAll.tsx` | `{ label: "This page" \| "This video", unsavedCount, done?: { count, target }, onAddLearning, onMarkKnown, onUndo }` | The block shared by the popup and the end card: uppercase label + (i) button toggling the explanation (closed by default), "N words not saved yet" / "Every word is saved", the two buttons, the done line with check icon + Undo. Explanation text differs: popup omits "You can turn this card off in Settings." — prop `cardNote: boolean` |
| `EndCard.tsx` | `{ title: "Video finished" \| "You reached the end", saveAll: SaveAllProps, onClose }` | Card with L badge, title, × close, and `SaveAll` inside |
| `styles.ts` | shared tokens (colors, fonts, button styles) | one place for the palette; also the brighter "on dark video" highlight colors from Main's `ovStyle` for M6 |
| `externalDictionaries.ts` | `dictionaryLinks(term, settings.dictionaries, pair)` | Cambridge `https://dictionary.cambridge.org/dictionary/english/<term-with-hyphens>`, Wiktionary `https://en.wiktionary.org/wiki/<encoded>`, Reverso `https://context.reverso.net/translation/english-japanese/<encoded>`, WordReference `https://www.wordreference.com/enja/<encoded>`; only the enabled ones, in that order. Unit-tested in Node |

All strings through `t()` (add keys to `src/i18n/locales/en.json`). Fonts: the mock uses Inter + Noto Sans JP (+ Noto Sans for IPA). Components set their font stack on their root; M5 decides how fonts reach the page's shadow root.

## Tests (Browser Mode, `*.browser.test.tsx`)
Mount each component in a real shadow root (like PageCard's test). Test behavior through roles and names: buttons call callbacks; status buttons show `aria-pressed`; IPA/sub/sections hidden when absent; (i) toggles the note (`aria-expanded`); done line shows "N words added to Learning" + Undo; links have the expected hrefs and `target="_blank"`; drag moves the window and stays inside the viewport; Escape closes the window (keyboard access). Plus one style-isolation check per component (page `* { color: red !important }` doesn't change the head text color).

## Mock comparison (before each commit that adds or changes a component)
Render a scratch page (not committed) with each component in the mock's example state (e.g. "figure out" learning with the mock's texts) and screenshot it next to a static rendering of the mock's markup for the same element; fix differences in layout, copy, color, size. Report the screenshot paths.
