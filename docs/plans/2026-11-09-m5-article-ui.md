# M5 — Article UI (content script)

> Executed with superpowers:subagent-driven-development. TDD; DOM code is tested in Vitest Browser Mode, the whole flow with Playwright E2E on local pages. Before committing a UI change, render it and compare with `project/Article.dc.html` in the mock.

**Goal:** on a page in the learning language, highlight words by category, show the hover card, open the dictionary panel on click, save words and phrases with their source, show the top-right card and the "You reached the end" card, record re-occurrences — per the spec's "Article UI", "Shared" and "Save all" sections.

**Architecture:** `src/content/article/` holds the page logic; it talks to the background only through `send()` (`src/messaging/client.ts`) and renders M4 components (`src/ui/lookup/`) plus `PageCard` inside the existing shadow root. Highlights use the CSS Custom Highlight API (no DOM rewriting).

## Decisions
- **When it runs:** not on YouTube or Netflix (the video UI owns those), not when `settings.sites.articles` is off, not on hosts in `neverRunOn` or `disabledSites`, and only when the page language matches the learning language: `<html lang>` first; if missing or too generic, `browser.i18n.detectLanguage` on a text sample (≥ 200 chars) with `isReliable`
- **Text model** (`page-text.ts`): walk text nodes under `document.body`, skipping `script, style, noscript, textarea, input, select, code, pre, [contenteditable], svg`, hidden elements, and Lingo's own host. Group text nodes into blocks by their nearest block-level ancestor. A block keeps `text` plus a map from text offsets to `(node, offset)` so a span becomes a `Range`
- **Visible range only:** an IntersectionObserver (rootMargin 50% of the viewport) on block elements; blocks are analyzed when they first come near the viewport, in batches (≤ 20 blocks or 20 KB per `analyze` call). A MutationObserver (debounced 300 ms) re-collects changed subtrees
- **Highlights** (`highlighter.ts`): one `Highlight` per category registered as `lingo-new`, `lingo-learning`, `lingo-known`; styles come from one constructed stylesheet added to `document.adoptedStyleSheets` (nothing is inserted into the page's DOM) containing only `::highlight(lingo-*)` rules: Learning = `background-color: #D3F1E5; text-decoration: underline 2px #0F9F7E` (approximating the mock's inset shadow with an underline), New = blue underline `#2F6FE4`, Known = gray underline `#A3A8B7`; `text-underline-offset` tuned to match the mock. Category toggles follow `settings.highlight` live (watch `storage.onChanged` through a `getSettings` + listener). If highlights can't be underlined (Firefox, later), use background colors only — not needed for the Chrome release; leave a single `supportsHighlightUnderline()` hook returning true and a TODO in docs/status.md
- **Hover** (`hover.ts`): `pointermove` (throttled to animation frames) → `document.caretPositionFromPoint` (fallback `caretRangeFromPoint`) → the span under the caret (phrase spans win) → after 250 ms show `HoverCard` (variant "article") above the word, flipped below if no room; it stays while the pointer moves into it, hides 200 ms after leaving both. Short translation from `lookup`; for phrases not in the dictionary, the built-in translator (see below)
- **Click** → `DictionaryWindow` variant "panel" (right side, below the PageCard). "On this page" = other sentences on this page containing the same key (from the text model); "Seen elsewhere" from `lookup.elsewhere`, `null` when unsaved. Status buttons call `saveTerm` (unsaved → saved, with source and the sentence) / `setStatus` / `removeTerm`; highlights update immediately for every occurrence of that key on the page
- **Sentences:** `Intl.Segmenter(lang, { granularity: "sentence" })` over the block text around the span
- **Source:** `{ platform: "web", url: location.href, title: document.title, lang }`; the background normalizes the URL
- **Phrase selection** (`selection.ts`): on `selectionchange` (debounced) with 2–8 words selected inside one block, snap to word boundaries (tokenizer offsets), show `PhraseBar` above the selection; saving creates a phrase term whose key is the base forms joined by spaces (via `analyze` of the selected text, taking each word span's key)
- **PageCard** shows the language line and highlight chips bound to `settings.highlight` (`setSettings`)
- **End of article:** the last block of the main content (prefer `article`, `main`, `[role=main]`, else the block with the most text's last sibling block) gets an IntersectionObserver; when it is visible and `settings.offerSaveAllAtEnd` is on and the page has unsaved New words, `EndCard` (kind "article") replaces the PageCard; × brings the PageCard back and it doesn't reappear on this page view
- **Save all:** keys = distinct unsaved New keys over all analyzed blocks of the page (not words inside the frequency level); `saveAll` then `undoSaveAll`; the content script also answers a `pageSummary` message from the popup (M7) with `{ supported, unsaved, done }` and `pageSaveAll` / `pageUndo` requests, so popup and card share one state
- **Re-occurrences:** after analysis, saved terms found on the page are sent via `recordEncounters` (one call per batch, with sentence and `{ textQuote }` position)
- **Built-in translator** (`translate.ts`, a `TranslationProvider`): `Translator.availability({ sourceLanguage, targetLanguage })`; create lazily on first need (inside the click/hover user activation when a download is needed); used for phrase short translations missing from the dictionary. If unavailable, the line is omitted
- **Warm-up:** after the first `analyze` on a page, the content script sends a `warmDictionary` request (new, no response payload) so the background loads the en-ja shards before the first hover/click lookup
- **Hover card `sub` line:** phrases → the main word's short translation (`figure — 数字、姿、人物` as in the mock); an inflected word → `loaves → loaf`; otherwise omitted
- **Pronunciation:** `speechSynthesis` with `lang = "en-US"`
- **Fonts:** content-script UI uses the font stack (`Inter`, `Noto Sans JP`, system UI) without loading fonts into the page — `@font-face` only works at document level and would affect the site. On pages without Inter the UI falls back to the system font
