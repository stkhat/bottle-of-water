# Architecture

MV3 / TypeScript / WXT + Preact, UI inside Shadow DOM. UI behaviour: [ui.md](ui.md); decisions and phases: [design.md](design.md).

## Parts
| Part | Role | Implementation |
|---|---|---|
| `LanguagePack` | Word segmentation (`Intl.Segmenter`), the vocabulary (rule E), base forms, frequency rank, **IPA**, phrase patterns with their own parts of speech and the language's **phrase matcher** (slots, gaps, detect vs select, the particles of phrasal verbs), parts of speech, the **names lexicon** and whether the language's capitals mark names ("Names and written case"), the **part-of-speech tagger** with the language's grammar of auxiliaries and participles ("Tags" below) | `en`: inflection table, frequency list, IPA table, phrase list and names lexicon built from kaikki (Wiktionary) and EJDict, tagger trained on UD English-EWT; `es` (kaikki Spanish, Wiktionary Spanish frequency list; no tagger yet) |
| `DictionaryProvider` | Short translation, the hover card's lines (up to three senses shortened like the short translation, pointers followed to the word they name: "Short lines" below; the senses of the word's tagged part of speech first: "Tags" below; computed when an entry is looked up, so packs carry nothing extra), details (meanings by part of speech) and an outline of each headword for rule A1, with the source each term came from | `en→ja`: EJDict-hand (public domain, bundled). EJDict has no part-of-speech labels: the data build labels its senses (`en-ja/pos.json`, "Tags" below), so the extension reads no Japanese glosses for them; `es→en` from kaikki's English glosses; `en→es`, `en→pt` from recipes ("Language data") |
| `TranslationProvider` | Translating one subtitle line / sentence. Several implementations tried in order ("Choosing a translation") | ① the site's translated subtitles (from `PlatformAdapter`) ② the browser's built-in translator (Chrome: Translator API). If neither exists, no translation |
| `PlatformAdapter` | Get the video element, fetch and parse subtitle tracks (**including the native-language track**), seek, detect the end, detect navigation; optionally say the page is a vertical short video (subtitle only), and that the player fills the window and can be narrowed for the transcript sidebar | YouTube (watch pages and Shorts) / Netflix |
| `TermStore` | Store and sync terms, sources and occurrences | IndexedDB (Dexie) + `BrowserSyncBackend` + Export/Import |

  - `core/`: browser-free logic. `lexicon/` (language packs, dictionaries, definitions, lookup, IPA, lemmas, sense labels and rule A2's `sense-order.ts`), `packs/` (loading, the lock, pack states, pairs), `phrases/`, `subtitles/` (parsers, transcript cards, translation alignment), `sync/` (codec, layout), `tagging/` (the perceptron, the `Tagger` part, English's tagger and grammar in `en.ts`), `text/`, `classify.ts` (statuses, `WordStatus`), `word-sense.ts` (rule A1), `names.ts` (rule D), `settings.ts`, `languages.ts`, `browser-env.ts`, `term-id.ts`, `url.ts`, `util.ts`
  - `background/`: the stores (terms, history, packs, settings, translation cache, `sync/`) and `handlers.ts`
  - `messaging/`: what pages and the background share. `protocol.ts` (every message and wire type), `client.ts` (`send`), `storage.ts` (`watchSettings`, `watchPackState`), `page-protocol.ts` (popup ↔ content script), `pack-status.ts`, `pack-wait.ts`
  - `content/`: runs on web pages. `article/` (`article.ts` over `state.ts`, `cards.ts`, `selection.ts`, `recorder.ts`), `video/` (`session.ts` over `state.ts`, `captions.ts`, `playback.ts`, `recorder.ts`, `summaries.ts`, `cards.ts`; the sites in `youtube/` and `netflix/`), `lookup/` (what both share: term lookups, the dictionary panel, the hover intent, the one-change-at-a-time queue, "Mark all"), `translate/` (the Translator API queue), `wiring.ts`, `shadow-host.ts`
  - `ui/`: components the pages and the on-page UI share. `styles.ts` (colors as `theme.ts` variables, highlight colors), `icons.tsx`, `Switch`, `Segmented`, `Meter`, `RowLabel`, `BrandHeader`; `lookup/` (hover card, dictionary window), `video/` (subtitle, transcript, menu), `backup/`, `packs/`, `format/`
  - `entrypoints/`: the background, the content scripts and the extension pages: `popup/`, `options/` (one component per section in `sections/`), `wordlist/`
  - `i18n/` (`t("key")`, `locales/`), `check/` (the check build's error log), `testing/` (helpers src tests share)
  - Outside `src/`: `scripts/` (data builds in `data/`, the check build's copy, the CLAUDE.md check), `tests/` (fixtures shared by Vitest and E2E, the manifest test), `e2e/` (Playwright)
- Where things run: a content script's IndexedDB belongs to the page's origin, so `TermStore`, `LanguagePack` and `DictionaryProvider` live in the **background** and content scripts / extension pages talk to it through typed messages. Pack data is read by the background in compact formats that reload quickly when the service worker restarts: bundled packs with `runtime.getURL` (not exposed as `web_accessible_resources`), downloaded packs from IndexedDB. Translating English definitions runs in the UI (content scripts, extension pages), since the Translator API does not exist in workers; the background keeps the results (`mtCache`)
- The UI on web pages sits in shadow roots: closed in production builds so page scripts cannot read it (it shows sentences kept from other sites), open in the check build and in development so tests and the developer can reach it. It acts only on events the user caused (`isTrusted`), not on events a page script dispatches: each shadow root drops untrusted UI events as they enter it (`guardShadowRoot`, `src/ui/from-user.ts`), and the handlers that open the dictionary or change a word check again
- IPA: EJDict-hand has no pronunciations, so the US IPA is taken from the `sounds` field of kaikki (English Wiktionary) and kept in the `LanguagePack`. Phrases show the IPA of their words joined together. Words without IPA hide the field. It is shown in dictionary style (`dictionaryIpa`): Wiktionary's syllable dots, tie bars, aspiration and diacritics are dropped, and ɹ/ɚ/ɝ/ɫ are written r/ər/ɜːr/l. It is set in Noto Sans where installed, else the system UI font, so every IPA letter comes from one font
- Getting video and text
  - **YouTube:** hook fetch/XHR in the page (MAIN world) and receive the `/api/timedtext` (json3) responses the player itself requests. Shorts have their own player (`#shorts-player`); the adapter goes by the URL and tells the page script which player each call is for
  - **Netflix:** hook `JSON.parse` in the page to read subtitle track URLs from the manifest, then parse TTML/WebVTT. Seek through Netflix's player API
  - Sync with subtitles via `requestVideoFrameCallback` + binary search over cues. Detect the video end with the `ended` event, or for a looping video (Shorts) its first seek from the last second back to the start
  - Code: `src/content/video/youtube/` and `netflix/`, each a MAIN-world `page.ts` (no dependencies), its `messages.ts` and the `adapter.ts` (`PlatformAdapter`). Both talk over `page-channel.ts` (`postMessage` to the page's own origin, shapes checked on both sides); `adapter-kit.ts` and `recent.ts` hold what the adapters share
  - Detect the end of an article with an IntersectionObserver on the last element of the body

## Language data
Research behind these choices (coverage per language, hosting alternatives, review findings): [notes/language-data-research.md](../notes/language-data-research.md).

| Unit | Contents | How many |
|---|---|---|
| Learning-language pack `<L>` | lemmas, frequency, IPA, parts of speech, vocabulary, phrase patterns, names lexicon and tagger model (`en` only so far) | one per learning language, shared by every native language |
| Pair dictionary `<L>-<N>` | words and phrases under the same keys (a phrase's key is its pattern, e.g. `make up one's mind`), one source tag per term | one per pair |
| English definitions `<L>-en` (`en-defs`, `es-en`) | Wiktionary's English definitions of L's words and phrases | the pair dictionary when N = en, the last fallback otherwise |

- Pair pack format (`<L>-<N>/dict-<n>.json` + `index.json`): `{ term: [short, [pos, text, hint?][], source] }`; `source` indexes `index.json`'s `sources`, `hint` is a translation table's English sense. `en-ja` keeps EJDict's format, with EJDict's capitalised headwords apart in `capital.json` ("Names and written case") and its senses' parts of speech in `pos.json` ("Tags"); its `phrases.json` (the translation tables' phrases) carries its senses' parts of speech as a third item ("Phrase data"). Every file stays under 4 MB (AMO rejects text files over 5 MB)

### Distribution
- A lock file bundled with the extension (`src/core/packs/packs.lock.json`, written by `npm run data:publish`) lists per pack its npm package, version, data `format`, whether it is bundled, and its files with size and SHA-256, plus the mirrors and the offered pairs. Data fixes ship with an extension release
- Downloaded packs: one npm package per pack in a public data repository, fetched from jsDelivr, then unpkg (both `Access-Control-Allow-Origin: *`, so no host permissions). Each file is checked against the lock's SHA-256 and stored in IndexedDB, one row per file (`packFiles`, `packVersions`). A new version is fetched beside the old one (stored hashes are skipped), switched in one transaction, then unreferenced files are deleted. A download stopped with the service worker resumes; retries go through `alarms` (1, 5, 30 min, then every 6 h)
- Fetched when a pair is chosen in Settings, when synced settings name a pair whose packs are missing, and when the lock changes. A stored version in an older `format` is not used. Packs of a pair no longer chosen stay until removed in Settings
- Without the data: requests that need a missing pack fail with `packsUnavailable`; the packs' state lives in `storage.local` (`packState`), which pages and Settings watch, and pages analyze again once it is ready
- **Hosting is not set up yet** (user, 2026-11-11): every pack is bundled; `en`, `en-ja`, `en-defs` stay bundled, the rest move to downloads with `npm run data:publish -- --download …` and a release. The E2E build `check-download` downloads `es`, `es-en` from a local mirror

### Native meanings and the quality gate
- Each pair has a build recipe (`scripts/data/recipes/`) merging sources in order; **per term, the first source that has it supplies all of it**: a bilingual dictionary (EJDict for en→ja), the native language's Wiktionary edition, English Wiktionary's translation tables. No pivoting through English at build time
- Terms no source has fall back to `<L>-en`, translated at display time (below); without a translator the English shows
- **Quality gate**: a pair is offered only when the human-made sources give a meaning for ≥ 95% of L's 5,000 most frequent content words (function words, contractions, letters and names not counted; user, 2026-11-11). `npm run data:stats` reports and checks it; `npm run data:publish` writes the passing pairs into the lock, which Settings reads
- Not used: ECDICT (its Chinese sources cannot be traced), build-time machine translation (the API's terms and output rights are unclear). zh is left for later (91.2%; the zh edition writes Traditional characters)
- The gate counts the vocabulary it was decided on, the dictionary's headwords: the words rule E adds (below; `data/gate/en-wiktionary-words.json`) are left out. Counted, they would put en-ja at 96.3%, en-es at 95.4% and en-pt under the gate at 93.7% (interjections, names, eye-dialect spellings such as "goin", abbreviations, and words of the 2010s)

### Vocabulary and frequency (rule E)
- **Vocabulary** (`en/vocab.json`; CORE rule in `scripts/data/vocabulary.ts`, run in `kaikki.ts`'s pass over the extract): EJDict's single-word headwords and every kaikki headword with the language's word shape (LEARNING: lowercase letters with inner apostrophes; hyphenated headwords never meet a token) that has a meaning of its own (a sense that is not an inflection, obsolete, archaic or a misspelling, in an entry that is not a proper noun; a spelling or clipping pointer counts: "anymore" → "any more", the form EJDict writes), is not a form the vocabulary already has (years, based) or a possessive, and is written in lower case at least 8 times, with its inflected forms, in other entries' usage examples and quotations from 1900 on (older quotations write older spellings). A word the examples write more often as an acronym joins only when its entry is that acronym (an abbreviation tag, or a pointer to its capitalised spelling): "ai" (a sloth) stays out, so "AI" gets no sloth. 6,328 words (40,197 → 46,525): um, hmm, wanna, kinda, cuz, anymore, app, website, laptop, podcast, selfie, chemo, opioid
- **Meanings**: a word the pair dictionary lacks shows its English definition (`en-defs`, which keeps every term some pair lacks), translated at display time like a phrase's ("Definitions translated at display time"). B1 imports the multi-word entries made of the new words too (73,112 → 75,554 patterns)
- **Names**: common words that are also given names join (jake, a young male turkey); rule D takes them for names where the document always capitalises them inside sentences ("Jake said"), and never takes an interjection ("Um") for one, though the names lexicon has "um" as a surname. A word the lexicon has only as another kind of name stays a word (Ted: "A Teddy boy"). Most names stay out: the examples write them capitalised (joey, pam, jim)
- **Frequency rank** (`en/freq.json`, `frequency.ts`): the TV list's words as base forms, as before; it ranks many of the new words it names (um 273, wanna 322, anymore 390, yo, hmm), which therefore move the list's other words down a little (rank 3,000 → 3,077, 10,000 → 10,674). A new word the list lacks is placed by how often the example corpus writes it, where the list's words are written about as often (`rankByExamples`: medians of blocks of 1,000 ranks, never above an earlier block's, interpolated on the log of the counts; written less often than the last block: unranked): blog 2,959, website 5,821, selfie 6,816, chemo 7,156 (1,101 words; 21,755 ranked, 19,089 before). EJDict's words the list lacks stay unranked: placed alike, Wiktionary's register would rank quotation words high (thence, viz, doubtless within 5,000)
- Size cut (the 50 MB guard): at 5 examples the rule adds 11,197 words and the packs reach 51.4 MB; 6 → 50.65, 7 → 50.10, 8 → 49.65 MB. Each step leaves about 50 to 100 more unknown tokens of the 171,709-token corpus (5 → 8: 3,763 → 3,979; the cut words are rarer ones: hitman, paralegal, voicemail). Capping the new words' definitions at 3 senses / 300 characters saves only 0.16 MB, so the threshold is 8
- Over the corpus (known level 3,000): word tokens without a hover 5,566 → 3,979 (YouTube 1,852 → 1,142, articles 1,521 → 1,238, Netflix 2,193 → 1,599); words shown as New per 1,000 tokens 77.5 → 84.4 (unknown words now New 5.4, the shifted ranks 1.5); names 929 → 1,051. Of 30 newly covered words judged in their sentence, 23 show a useful meaning, 1 a partly fitting one, 6 a wrong one (cuz → "A cousin", kinda → a baboon, aka → a vine, Nov → "A novice", should've, Ted Beneke → "A Teddy boy")
- Capitalised abbreviations (2026-11-14): a word written with a capital that EJDict has no lower-case entry for takes EJDict's abbreviation headword before the rule-E word's definition ("Nov" → "Nov." → November → 11月, not "A novice"; Mon → 月曜日, St → 通り…, Wis → Wisconsin), each sense that spells the abbreviation out becoming the first sense of the word it names, with that word as its hint. A word EJDict has keeps its own senses ("the Sun" is no Sunday; Miss, Wash, Mass). A lower-case pointer to a letter-case form takes that form's definition ("aka" → AKA's "in other words, i.e."; gif, dna, catch-22: 219 words that showed "Alternative letter-case form of …")
- Not yet: names in caseless documents (as for rule D); "Jan" and other abbreviations rule E did not add stay without a hover

### Phrase patterns
- A pattern is words and slots (`one's`, `someone`, `something`, `oneself`; Spanish `alguien`, `algo`) with flags `detect` (automatic highlighting) and `gap` (words may come between parts, as in phrasal verbs). A pattern's word matches a token's written form or any base form, so keys keep Wiktionary's wording
- Each language's phrase matcher (`LanguagePack`) fills slots (English possessives → `one's`, object pronouns → `someone` / `something`, reflexives → `oneself`) and applies the gap rule
- Detect mode (highlighting): contiguous `detect` patterns without slots; saved phrases also match with slots and gaps. Saved phrases are placed first, the longest first (words from first to last, gap words included; then the most pattern words, the earliest start, the key), each where it overlaps no phrase placed before it, so a phrase saved over part of a shorter saved one is drawn and, of two the same length, the earlier one; detected phrases fill only the words outside them, so a saved phrase wins over a detected one even when the detected one starts earlier or is longer
- Select mode (a selection, `PhraseMatcher.matchSelection`): every pattern, but only one whose first-to-last word (gap words included) spans every selected word and has at least two of its words selected; among those the most pattern words win. The sentence decides when the selection is part of a longer pattern ("made up" → `make up one's mind`, "made it up" → `make up`); a selection that reaches past a pattern, or holds a shorter one, is its own words ("gave up the crust" → "give up the crust")
- A phrase with a gap becomes one span per contiguous part (same key, part number); words in the gap keep their own spans. A phrase span whose key has a slot another word fills is marked `slot`. A selection is saved under its pattern's key, else under its words' keys
- Snapping a selection (`core/selection.ts`): to whole words; a detected phrase, and a contiguous saved phrase the selection covers only part of, count as their words (the key's word for each); a saved phrase the selection covers whole, one with a `slot` and every part of a phrase with a gap widen the selection to the whole phrase
- **Phrase parts of speech** (LEARNING data, `PhrasePatterns.pos` in `en/phrases.json`, `phrases/phrase-pos.ts`): each pattern's own parts of speech in kaikki (verb, adv, prep_phrase, intj, particle, phrase, noun, adj…), the one with the most usable senses first, one letter code per pattern of `detect` and of `more` ("vi": a verb, then an interjection); 72,013 of 73,112 patterns have one (EJDict's alone have none). `intransitive` lists the verb patterns with a sense kaikki marks intransitive and none marked transitive or naming someone / something in its gloss: 1,001, weak data, read by one rule only

### Phrase data (rules B1, B2, B2b, B4, C1, C2)
Built by `scripts/data/phrases.ts` (patterns, Japanese phrase meanings) and `scripts/data/en-defs.ts` (English definitions); every rule reads the source's own structure and statistics, never a list of phrases. Layers: CORE (`idiomaticity.ts`, `senses.ts`, `examples.ts`), LEARNING (`PhraseLanguage`: which kaikki parts of speech are discourse, nominal, content, names; slots, auxiliaries), GLOSS (English glosses: usage and literal notes; stopwords are the source's own most frequent gloss tokens), NATIVE (`NativeGlosses`: Japanese content units are kanji and katakana runs; a katakana-only gloss is a loanword), PAIR (EJDict, the translation tables)
- **B1, every multi-word entry**: each kaikki entry with a sense of its own (not form-of / alt-of, obsolete, archaic, a misspelling, a literal note or a non-constituent) whose words are vocabulary words, their inflected forms or possessives ("for God's sake"), at any word rank, plus EJDict's multi-word headwords. A multi-word noun or name needs a translation table or an occurrence in the example corpus (44,785 unattested compounds left out). 73,112 patterns (19,932 before): 28,482 `detect`, 44,630 `more`, 4,726 with a gap; all matchable on selection
- **Example corpus** (`examples.ts`): every usage example and quotation of the extract with the entry's own headword cut out where kaikki marks it in bold (English: ~21 million tokens); counts each pattern's words as written or inflected
- **B2, idiomaticity** (replaces the rank rules of 2026-11-11): score = Σ wᵢ·opacityᵢ / (Σ wᵢ + 0.3·log10(1 + count) + literal note). A sense's opacity is 1 − the share of its gloss tokens found in its words' own first glosses (at least 0.9 when the source tags it idiomatic or figurative, or for a discourse pattern: interjection, phrase, particle); its weight is √(1 + translation-table languages) × 0.9^rank × e^(−0.5 × label penalty) (rule C2's labels, usage notes aside). For a content pattern with a Japanese gloss, 30% of the score is 1 − the share of its kanji/katakana found in its words' EJDict glosses. Detected when score ≥ 0.55 + 0.03·log10(1 + count) + 0.1·max(0, 3.5 − PMI), PMI being log2 of observed over expected co-occurrence in the example corpus. Never detected: slot patterns, patterns starting with be / have / do. The source's phrasal verbs (its "phrasal verbs" categories) are detected whatever their score: a verb and particle's gloss overlaps its verb's long sense list ("come back" → "To return"), and P2 ("Phrase precision") checks each match. Patterns under the threshold stay in `more`
- **B2b, transparent compounds**: a nominal pattern (noun, adjective, name) whose first definition names every content word ("digital signature"), or a nominal or discourse pattern whose Japanese gloss is a katakana loanword (instant coffee → インスタントコーヒー) or shares at least half its kanji/katakana with its words' glosses ("I don't know" → 分からない), is not detected
- **B4, named entities**: a pattern whose entries are all proper nouns or all written in Title Case (New York, American Revolution), or an EJDict headword written only in Title Case, is not detected; it stays available for lookup
- **C1, Japanese meanings** (`en-ja/phrases.json`, the translation tables' phrases EJDict lacks: 7,270, 901 before): up to four senses, each `《English sense》word,word` (EJDict's note style; up to three words, each word once, in the best sense that has it), ordered by the senses they translate (C2); a table at entry level goes to the sense its label matches. The third item gives the senses' parts of speech, the source's own ("break up": 別れる,手を切る then 壊れる; "you know": interjection)
- **C2, English definitions** (`en-defs`): a term's senses ranked by the source's labels: a usage note (+1; "Used…", "Said…", a definition that describes a figure of speech: apophasis, rhetorical question, and for a phrase's sense that is not nominal a definition that only names its function: "A mild intensifier", "A phrase used at parting"; `isUsageNote`), a register label (vulgar, dated, rare, slang…: +1.5), a pointer (+2); for a phrase also a domain topic (+1.5), a regional label (+0.75), and its part-of-speech blocks ordered by their translation tables ("send out" as a verb before the noun), a translated sense lifted by up to 1.5; ties keep the source order. A pointer sense ("Synonym of X", "Clipping of X", an alternative spelling) takes X's best definition (9,161 senses); inflections ("Plural of X") are left out. Each sense keeps its part of speech, which rule A2 and the discourse markers read. A term every English pair dictionary has (en-ja, en-es, en-pt) is left out: no lookup reaches it (25,470 terms; rebuild the pairs' recipes before en-defs). Tried and dropped (2026-11-14): lifting a phrase's senses the source labels figurative or idiomatic above its literal ones. It would put "get around" an obstacle (figuratively) before moving round it, but the labels are uneven: over the corpus 139 phrase hovers changed, most for the worse ("get it" ×48 → to receive punishment, "put up" → to house); with verbs and "figuratively" only, 42 changed, 15 better and 8 worse ("go to sleep" → paresthesia, "come across" → to change sides)
- EJDict's phrase senses are labelled like its words' (`en-ja/pos.json`, "Tags") when their pattern has several parts of speech in Wiktionary
- Sizes (all packs bundled; under 50 MB together, `pack-sizes.test.ts`): `en` 4.87 → 5.93 MB (phrases 0.46 → 1.53 MB, 133 → 431 KB gzipped), `en-ja` 7.04 → 7.73 MB, `en-defs` 13.35 → 18.56 MB, `en-es` 3.26 → 4.32 MB, `en-pt` 2.63 → 3.42 MB; all packs 37.7 → 46.5 MB raw, 10.5 → 12.6 MB gzipped; with rule E's words (2026-11-13) 49.65 MB raw, 13.4 MB gzipped ([data-sizes](../notes/data-sizes.md))

### Phrase precision (detect mode)
Precision before recall (user, 2026-11-13). Every rule is grammar or the source's own labels, never a list of phrases. At each word the longest dictionary match decides; when it breaks a rule, no dictionary phrase starts there (a shorter one does not stand in: "so long as" is no "so long") and its words are classified as words, with their tags (A1, A2, D). Saved phrases and selections are not checked. `core/phrases/fit.ts` (`phraseMisfit`, CORE) reads the pattern's parts of speech, its words' main parts of speech (`LanguagePack.partsOfSpeech`), the language's particles (`PhraseRules.particles`) and each word's tag and closed class from the tagger (`Tagger.role`: determiner, noun-phrase start, object, modal or do-auxiliary, infinitive marker, preposition, subject, partitive, be, past participle). Without a tagger only P1 applies
- **P1, utterances**: a pattern whose only part of speech in the source is "phrase" (a whole utterance: "to be honest", "what's up") is never highlighted; it stays available to selections
- **P2, adverbial particle**: a two-word verb pattern ending in a particle is highlighted only where the particle's trusted tag is an adverb (RP/RB: "find out", "give up"), or a preposition follows it ("sneak out of here"); "come to" + a place, "talk about", "look at", "fill in the form" are words. An untrusted tag keeps the match, unless the particle is one the language never uses as an adverb (`PhraseRules.prepositions`; English: at, for, from, into, of, onto, to, toward(s), upon, with): "going to try", "went to Broadway"
- **Context**, by the pattern's main part of speech; punctuation between the phrase and a neighbour cuts the link:
  - adverb: not after a determiner when a word of it is mainly a noun, unless a verb, adjective or adverb follows ("the first thing we need"); one ending in a preposition not before a personal pronoun, its object ("this isn't just about you", "kind of you"; "just about everyone", "just about done" stay)
  - prepositional phrase: inside a clause (a word before it, no pause), not before a noun phrase ("in advanced talks", "seat D in Green Class"), unless it ends in a preposition; one ending in a determiner or pronoun not before the partitive "of" either ("after all of that"; "as a result of" stays)
  - interjection or particle: not after a modal or do-auxiliary ("do you know"); one not starting with a pronoun also not after a determiner, the infinitive marker or a preposition ("a good day", "for so long"); one starting with a verb not after a subject ("he got it"); one ending in a verb not before an object, in a punctuated document ("you know the guy"); one that is a whole clause with its object, its subject a personal pronoun ("you tell me", "you hear me"), not next to another word of a sentence, in a punctuated document ("why don't you tell me what's going on", "you told me that…"). "don't", "doesn't" and "didn't" count as do-auxiliaries, and "--" as a pause
  - adjective or noun (no verb among its parts of speech): not where a word of it is tagged as a bare verb ("I have to go" is no "to go", 持ち帰り)
  - verb: not when its first word is tagged as something else after a determiner, an adjective or a number ("take that mask off", "a deadly pile up"; after a subject a noun tag is more often the tagger's mistake: "boyfriend break up"); not a past participle right after "be" whose particle opens a noun phrase ("to be passed up the chain"); not an intransitive pattern whose particle is tagged as a preposition before a determiner or number
- **Discourse markers** (`markerPos`): a phrase the source also has as an interjection or particle, at a clause start (the block's start or after punctuation) and not before an object, gets `pos: "interjection"`, so its lookup shows those senses first (rule A2: "Come along, children" → "Expression of encouragement…" instead of "To accompany"). Sources with labelled senses change: Wiktionary's definitions, the translation tables' phrases (their parts of speech, "Phrase data"), the pair packs, and EJDict's phrases whose patterns have several parts of speech. Over the corpus 923 phrase spans are discourse markers; 186 hovers show other senses first (all right 142: 畏まりました,了解,オーケー before 大丈夫な; shut up, get out, not at all)
- **Punctuation** (`DocumentCasing.unpunctuated`, from the content script's casing pass): a document of at least 50 words with fewer than one comma per 50 is unpunctuated (speech recognition); there a verb-final interjection's object rule is off
- English's particles: about, above, across, after, against, along, apart, around, as, aside, at, away, back, before, behind, below, beneath, beside, between, beyond, by, down, for, forth, from, in, into, of, off, on, onto, out, over, past, round, through, to, together, toward(s), under, up, upon, with, within, without. Spanish has none (P2 is off)
- Measured over the translation-quality corpus (171,709 tokens), the clause and preposition rules of 2026-11-14: 26.8 → 26.7 (Netflix 31.0 → 30.7); the 23 highlights removed are all wrong matches (you tell me 20, kind of you 2, just about you 1), the 178 judged highlights are unchanged
- Measured over the translation-quality corpus (171,709 tokens): phrase highlights per 1,000 tokens 18.4 → 14.9 (YouTube 17.3 → 14.1, articles 14.9 → 13.0, Netflix 20.9 → 16.7); classifying ~3.4 → ~3.6 ms per 1,000 tokens (Node, dev Mac). With the phrase data of B1–C2 (2026-11-13): 14.9 → 26.8 (YouTube 14.1 → 28.1, articles 13.0 → 12.6, Netflix 16.7 → 30.9), mostly discourse markers and idioms of common words (you know, all right, a lot, kind of, of course); classifying ~3.5 → ~3.8 ms

### Definitions translated at display time
- The English definition is translated, not the phrase ("spill the beans" → "To reveal a secret." → 秘密を漏らす). Leading labels are dropped; pointer senses ("Alternative form of …") stay English
- A definition that is only a usage note (`isUsageNote`: "Used to…", "Said…", an apophasis or rhetorical question) is not translated for the hover card, the window's short meaning or the lists: the term as written is, as a phrase no dictionary has ("not to mention" → 言うまでもありません; "you see" → わかります), marked "Machine translation"; the window keeps the definitions. Judged with Chrome's translator over the 22 such terms of the corpus (94 uses): better in 71 uses, worse in 12 (my goodness → 私の良さ, suck it, made you look, oh man, no relation), alike in 11
- For a phrase, a usage note is also a definition that names what the phrase is or does instead of meaning it (2026-11-14, NATIVE: English glosses), read with its sense's part of speech and only for one that is not nominal (a noun's "A word used to…" is its meaning; the nominal labels are `NOMINAL_POS`, the data build's `ENGLISH_PHRASES.nominal`). Three shapes of the gloss head: a head noun phrase followed by a reduced relative clause ("A phrase used at parting", "A greeting said at noon", "Expletive used for emphasis"; "used/said/uttered" followed by a preposition, an -ly adverb, punctuation or the end); a head noun that names a class of expressions by function, after an article or a modifier (the source's own function categories: intensifier, filled pause / filler, hedge, discourse marker, greeting, farewell; or "indication of/that"); "Serves/Functions as …". "An expression of surprise", "An exclamation of greeting" and a bare "Farewell." stay meanings, and pointers stay as written. A word's function label is not one: its literal translation would be the word itself ("gon"), and its first sense is its main one. Measured in docs/notes/translation-quality.md "Function-label definitions"
- The hover card shows a translation as one line (`translatedLine`): each comma item once, no final 。, within the Japanese cap. Japanese puts its main verb last, so a long line first loses its notes in brackets (and a particle a note leaves behind), then keeps the longer of its longest head that ends a clause of its own (not …て, …たり, …ために, …を) and its longest tail after a comma, else its longest tail after a particle; the window shows the whole translation. Over 264 definitions translated by Chrome: display width median 32 → 30, 90th percentile 66 → 46, over the cap 23% → 0%
- The Translator API does not exist in workers, so the UI translates and the background caches the results (`mtCache`, keyed by L, N and the cleaned text; 20,000 rows, least recently used out; cleared with the pair's packs; device only). Whether it can run is detected in the UI
- The hover card translates the first sense, the dictionary window up to four. One queue per page with the subtitle translator: current subtitle line, then the window, then the hover card, then lists
- **Lists** (2026-11-14: the video's Words tab, an article's "Words on this page", the word list page with its own translator) translate the first sense of the rows they render at that lowest priority, and pick up translations the hover card and the window make (the summaries a list reads from are updated as results reach the cache). Without a translator the English shows
- Creating a translator for a pair Chrome still has to download needs a user gesture: Settings starts it when a pair is chosen, the dictionary window when it opens; hover cards show English until then

### Short lines (the hover card)
`core/lexicon/short-lines.ts` makes each entry's `short` at build time and the hover card's lines when an entry is looked up, one sense per line. The rules are layered so another pair brings only its own parts:
- **Language-independent**: the first sense is the text up to the first sense separator outside brackets. A line is capped by display width (wide characters count 2): a longer one first loses its parenthesized notes ("(…が生れつき備えている)能力,力" → "能力,力"), then is cut at the last comma that fits, else cut hard with "…". Repeated comma items are dropped. A pointer sense stays whole
- **Pointers** (`shortLines`): a sense that only points to another word, a form ("goの過去", "Plural of casa") or a reference ("=anyhow", "Synonym of look for"), is followed one hop to the entry it names, within the same source. A form that is the first sense stays first with its target's first meaning, then the entry's own meanings, then the target's (went → goの過去, go's first two meanings; found → findの過去・過去分詞, find's first meaning, …を創設する). Pointers are followed only from such a first form or from an entry with no meaning of its own: a pointer after the entry's own meanings marks a lesser use ("them": "=those"). A pointer that names several words ("am not, is notの短縮形") or glosses its target ("Synonym of deal with (“to behave …”)") is not followed. `short`, the dictionary window and the word list keep the entry as it is
- **Per gloss language**: Japanese separates senses with `;` `／` `・` (not inside a katakana name) and a space between two Japanese glosses (not inside Latin text), drops kana readings after kanji (戴冠(たいかん)式 → 戴冠式), writes pointers as "Xの過去…" / "=X", and caps at 25 characters. English definitions separate senses with `;`, write pointers as in `definitions.ts` (`definitionPointer`), and cap hover lines at 40 characters; their `short` is not capped, since it is what the translator gets; its translation is capped when it is shown (`translatedLine`, "Definitions translated at display time")
- **Per source**: EJDict's 〈C〉/〈U〉 and {形}-style marks are removed
- The base form and the senses a word's part of speech asks for come from its tag ("Tags" below)

### Tags: base forms and senses by part of speech (rules A1, A2)
A word's tag in its sentence decides which entry the hover looks up and which senses it shows first. The rules are layered like the short lines; a learning language without a tagger (Spanish so far) leaves them off and nothing changes:
- **Tagger** (LEARNING, `LanguagePack.tagger`, `core/tagging/`): `tag(sentence tokens)` gives each token a tag, its dictionary part of speech (`label`), whether it is an inflected form, whether it is a proper noun, and a confidence; `threshold` says from which confidence a tag is trusted; `uses(tagged words)` is the language's grammar of how each word is used. English: an averaged perceptron (Penn Treebank tags) trained on UD English-EWT by the data build (`en/tagger.json`, `scripts/data/tagger.ts`; small weights pruned), with no dependencies. Contractions are split for the tagger only ("do" "n't"); ALL-CAPS documents (casing mode "upper") are tagged in lower case. Its grammar: auxiliaries (have + past participle or "to", be + participle, do + bare verb, get + past participle, with up to three adverbs or an inverted subject between: "has spent", "does Harvey know", "had to", "got hurt"); how an inflected verb is used (finite, after an auxiliary, before a noun "demanding work", a state "was established" without "by"); a gerund after a determiner or adjective is a noun; where a participle can stand for a preposition (clause start, after a pause or a noun)
- **Trust** (CORE, `trustedTag`): a tag counts only from the threshold (English: a margin of 5, which keeps about 90% of EWT's content words at about 97%), never as a proper noun (a name has no word sense; "Deposit my specimen"), and only when it agrees with the word's form (a form that is not a headword cannot be a bare noun: "calmer")
- **Where it runs**: the background tags each block once, sentence by sentence, while it classifies it (`analyze`, `recordHistory`; `word-sense.ts` `readWords`), not per hover; the phrase rules read the same tags ("Phrase precision"), with or without the dictionary. The span carries the result: its key (rule A1) and `pos` (rule A2), which the lookup sends (`lookup.pos`). With a tagger, `analyze` loads the dictionary to outline headwords (`DictionaryProvider.outline`); while the dictionary is not on the device the words keep their keys and the highlights do not wait. The first `analyze` after a service-worker start therefore parses the dictionary (~90–100 ms in Node) for every English document, which before the tagger only documents with capitalised words did (rule D); end to end the first highlights take the same time on the E2E article (cold ~423 ms, after a restart ~392 ms, before and after the tagger and with the phrase rules), so the first highlights are not split from the dictionary load Tagging takes ~1.5 ms per 1,000 tokens, classifying ~3.3 ms instead of ~1.5 (Node, dev Mac)
- **A1, base form** (CORE, `chooseKey`, for unsaved words that are not names or capitalised): an auxiliary keeps its entry while that starts with a pointer ("has" → haveの三人称単数現在, then have's meanings), and an entry with a meaning of its own goes to the base ("being" → be); a written form that is not a headword takes the base the tag's part of speech fits, then the most frequent ("arises" → arise); a participle not used as a verb keeps its own entry when that has a meaning (prenominal, a state, "are we done"), as does one where a preposition can stand when its entry starts with a preposition ("Including taxes"), and a gerund noun whose entry has nouns; otherwise a word tagged as an inflected verb goes to its verb base (decided → decide, wearing → wear, saw → see) unless its own entry says it is that base's form and adds a meaning right there, or is nothing but pointers (went: goの過去 and go's meanings, as the short lines follow them). Comparatives keep their own entries ("later" → 後で). The key is what the word is saved under, so "save all" saves decide, not decided
- **A2, senses by part of speech** (CORE, `senseOrder`): the hover's lines move past the first sense only on positive evidence: the first sense's label is stated (not taken from its neighbours; a noun guess does not count against an adverb tag) and conflicts with the tag, and the entry has senses of the tagged part of speech. Those come first, with an unlabelled sense right before one of them (EJDict leaves block heads unlabelled: attempt → 企て,試み), the first core translation (EJDict's 『』) leading (fine/JJ → りっぱな, just/RB → 単に, like/IN → …に似た). The dictionary window keeps the dictionary's order; an entry shown by its English definition takes its short meaning from the first of them
- **Sense labels** (NATIVE and PAIR, at build time, `scripts/data/sense-pos.ts` → `en-ja/pos.json`): sources with labels (Wiktionary's definitions and translation tables) need nothing. EJDict's senses of words with several parts of speech are labelled, one code per sense (`sense-labels.ts`), from a pointer's grammar ("seeの過去" → verb, "複数形" → noun), EJDict's markers ({形} {名} {動} {副} {間投}; 〈C〉/〈U〉 in the first item → noun), 《》 notes that name a part of speech (a note alone heads the senses after it), the Japanese gloss's main item (…を / 〈人〉に or a verb ending → verb, a leading "…" → preposition, な / い / の → adjective, に / く / て / と → adverb, "…く" followed by "…に" → adverb, a kanji or katakana ending → a noun guess), and gap filling (an unlabelled run between two senses of the same part of speech, not after a pointer). Only parts of speech kaikki gives the word count (or the nearest it has). 86% of those senses get a label; the dictionary window shows the labels not taken from neighbours
- English's tagger reads gonna, wanna and gotta as the treebank writes them ("gon" "na": a verb, then "to")
- Not yet: tags on caption labels ([sighs] read as a noun); names in caseless documents

### Names and written case
How a word is written on the page decides which meaning it shows, and whether it is a word at all. The rules are layered like the short lines:
- **Document casing** (`core/text/casing.ts`, language-independent): the content script reads a whole document before it is classified: a video's caption track (`content/video/session.ts`), an article's main content (`content/article/article.ts`, Title Case menus and links outside it say nothing; YouTube comments: every comment). Its mode is "upper" when over 60% of the words are ALL CAPS, "lower" when under 0.3% of the words inside sentences are capitalised (speech recognition), else "mixed". In mixed mode it counts, per word, the capitalised occurrences inside sentences and the lower-case ones. A word does not count at a sentence start (the sentence segmenter), after a colon, an opening quote, a closing bracket or a dialogue dash ("- Aww"), anywhere in a block in Title Case without a final period (a heading), inside brackets ([sighs], (Laughter)); ALL-CAPS words and plural acronyms (AEDs) count for nothing. `analyze` and `recordHistory` carry this casing (only words capitalised inside a sentence at least once); an article updates it as blocks come and go and classifies again the analyzed blocks with a word whose verdict changed. Nothing runs per hover
- **Written case** (`capitalHere`): in a mixed document a word is capitalised in a way that counts inside a sentence, at a sentence start when the document writes it capitalised at least five times as often as in lower case, and as an acronym when ALL CAPS among words that are not (US, not "GIVE US MORE"). The span gets `capital`; the lookup sends `written` ("capital", "upper", or "lower" for a word in lower case in a mixed document; nothing for a caseless document or a capital at a sentence start, and the word list sends nothing)
- **Rule D, names** (`core/names.ts`): in a mixed document a vocabulary word is a name when the document capitalises it inside a sentence and never writes it in lower case, and the names lexicon has it: as a given name, or as a surname, place or organisation that is rare as a common word (beyond rank 3,000: Trump, Thatcher; not World, Park, Center), and not as a capitalised common word (English, Christian). Never names: a word whose main part of speech is a function word or an interjection (The, Yes, Oh), a word right after a determiner ("the Enlightenment"). A caseless document has no names. A name whose dictionary has a capitalised meaning of its own stays a word, capitalised: a gloss that says what it is (June → 6月, Japan → 日本), or the name in the native script for a word that is not a person's name first (Germany → ドイツ). Every other name is `ignored` (`Span.name`): no highlight, no hover, and the sentence history does not index it. Languages without case or that capitalise every noun turn this off (`LanguagePack.namesByCase`); so does a pack without a names lexicon (Spanish so far)
- **Names lexicon** (LEARNING, `en/names.json`): Wiktionary's proper-name entries by lowercase word → their kinds (given name, surname, place, organisation, other), the main one first, and "!" for a word that also has a capitalised adjective, adverb, verb or interjection entry (English, Monday, God). Only vocabulary words and given names (15,709; 57 KB gzipped)
- **Capitalised headwords** (PAIR, `en-ja/capital.json`): EJDict merges case variants into one key with the lowercase senses first (japan → 黒い漆, 『日本』 last). The build keeps the senses of capitalised headwords apart: under the lowercase key for a capitalised word (japan → 『日本』, may → 『5月』), under the key in capitals for an acronym (US → 合衆国). A key with a lowercase headword keeps only its lowercase senses in the dictionary; a key written only with capitals keeps them there too and is listed under its lowercase key (Paris, David). Capitalised: those senses first when they mean something (`capitalMeaning`: not about one person, a people or a symbol — EJDict writes those with a lifespan, 聖, …人, 記号, or a work's title in brackets — and with a Japanese gloss, or an acronym's expansion); lower case: the lowercase senses alone; not said: lowercase, then capitalised. The dictionary window follows the same lookup; word lists show every sense, as before
- **Runs of capitalised words** (`documentNames`, `DocumentCasing.runs`: each word the document writes capitalised right after another capitalised word, only a space between and not at a start): a name is read whole. A vocabulary word the document always capitalises that the lexicon lacks is a name when it comes right after a person's name or another word of one (Harvey Specter, Pearson Specter Litt), and is rare as a common word as rule D asks of surnames (not Center in "Kennedy Center"); it keeps a capitalised meaning of its own as rule D does; titles come before a name and stay words (President Trump). A word rule D takes for a name only as a place or an organisation stays a word after a vocabulary word that is no name: the head of a title (Persian Gulf → 湾, Recording Academy, Democratic Republic). Over the corpus: 49 tokens become names (Specter 17, Williams 7, Scrooge 6, Keys, Hanks, Jobs, Spears; also a few title words such as Diaries, Declaration, Division), 16 stop being names (Academy 9, Republic 2, Petroleum, Alliance, Enterprise, Capital; Bunny of "Bad Bunny" wrongly)
- Not yet: names in caseless documents (CHANDLER in ALL-CAPS captions); names lexicons for other learning languages

## Choosing a translation
Use the site's translation when it has one; fall back to the browser's built-in translator only when it doesn't. Site translations are often human-made and need no on-device processing.

| Order | Source | YouTube | Netflix | Articles |
|---|---|---|---|---|
| 1 | The site's **native-language subtitle track** (human-made) | manually added Japanese subtitles | Japanese subtitles | — |
| 2 | The site's **machine translation** | auto-translation of the original subtitles (fetched with `tlang=ja`) | — | — |
| 3 | **The browser's built-in translator** | Translator API | Translator API | Translator API |
| — | none | no translation | no translation | no translation |

- Pick one per video and never switch midway. When a video uses the site's translation, lines without a translation are not filled in by the built-in translator (meanings would overlap and the phrasing would clash)
- **Timing**: a site's native-language track has different line breaks and timestamps from the original (especially Japanese subtitles on Netflix)
  - Subtitle translation: look up the translation track separately by playback position and show the translation on screen at that moment as is
  - Transcript cards (rule G, many to many): each translated cue goes to the card (sentence) it overlaps most in time (ties to the earlier card), and also to every other card of its kind (spoken or sound label) that it covers at least half of, so a condensed line spanning two sentences shows on both. A card joins all its cues in time order. A spoken line goes to a sound-label card only when it overlaps no other card. The half was measured on human Japanese tracks timed apart from the English (and on the same tracks condensed): it leaves almost no card without a line while lines with a neighbour's text barely grow; a lower share mostly adds grazing neighbours, and asking the cue to lie mostly in the card too gives back most of the empty cards. YouTube's machine translation of an auto-generated track keeps its own rule (cards follow its sentences, see "Transcript")
  - YouTube's auto-translation of a manual track comes back with the same breaks as the original, so map it one to one; for an auto-generated track the cards come from its sentences (see "Transcript")
- The occurrence's `translation` stores the translation shown at that time
- Articles have no site translation, so only the built-in translator is used

## Data model (IndexedDB)
- One Dexie schema version (4). Versions 1–3 only added tables and were merged into it (2026-11-12); Dexie upgrades an older database by comparing the schemas
- `terms`: `{id: "en:look up", lang, key (base form or sequence of base forms), display, kind: word|phrase, status: learning|known, bulk?: bool, note?, createdAt, updatedAt}`
  - Words saved by "save all" (Mark as Known at the end) get `bulk: true` (for demotion when sync space runs out)
- `sources`: `{id, platform: youtube|netflix|web, url (normalized), title, lang, firstSeen, lastSeen}`
- `occurrences`: `{termId, sourceId, sentence, translation?, pos: {timeMs}|{textQuote}, seenAt, origin: saved|encountered}`
  - Saving always creates one source record
- Sentence history (device only: never synced, not in the JSON export)
  - `historyPages`: `{id (= source id), platform, url (normalized), host, title, lang, firstSeen, lastSeen, bytes}`
  - `historySentences`: `{pageId, text, translation?, pos, keys: termId[], seenAt}`, unique per page and text, indexed by `keys` (every base form of each word outside the 300 most common, plus the phrases found in the sentence)
  - Articles keep the sentences of the blocks Lingo analyzes; videos keep **played lines only**. Not kept while the switch is off or on hosts in "Never run on" / switched off in the popup; adding a host to "Never run on" removes its pages. Size is counted by Lingo (UTF-16 size of the strings plus a fixed overhead); over 50 MB, the oldest pages (`lastSeen`) are removed until under 45 MB
  - Saving a word (not "save all") copies its kept sentences into its occurrences (`origin: encountered`, up to 50)
  - Meeting a saved word again records it automatically (deduplicated by source + sentence, at most 50 per word; the oldest encounters go first, the sentences the word was saved from always stay)
  - YouTube links use `&t=` to jump to the spot
  - Only pages/videos opened with the extension on are recorded
- Settings live in storage.sync: language pair, interface language, frequency level, highlight categories, external dictionaries on/off, subtitle position, translation visibility (subtitle / transcript), subtitle text size and background, what to do with unsaved New words at the end, per-site on/off and the exclusion list, and the L button's on/off per video platform

## Sync (browser `storage.sync`; limits: ~100 KB total, 512 items, ~8 KB per item)
- `BrowserSyncBackend` (background) owns it. A backend for the user's own cloud (future) would sit beside it; no interface is kept for it until then
- The limits are the same in Chrome and Firefox. Use the `storage.sync` constants (`QUOTA_BYTES` etc.) when readable at runtime, otherwise the values above
- Per language, sort `term key → status code + updated time (minutes in base36)`, concatenate, gzip (CompressionStream) + base64, and store in chunks of ~7 KB
- **Rough capacity**
  - Uncompressed: **~6,000 words**
  - Compressed: **~12,400 words** (English, measured 2026-11-09 with realistic save times; 20,000 words take ~170 KB)
  - Words within the frequency level do not count
  - When the limit gets close, demote words saved by "save all" to "this device only"
  - Over 90% of the room left by other keys (settings, other languages): leave out "save all" words oldest first; if that is not enough, leave out the oldest known words too and report how many. They stay on the device
- Merge: per word, the newer update time wins (same minute: keep this device's); deletions are tombstones, carried for 90 days. Pick up other devices' changes with `storage.onChanged`
- Each push reads and merges the synced copy before writing it (chunks first, then `sync:<lang>:meta` = `{chunks, updatedAt, v}`, then stale chunks are removed), 2 s after the last local change. Pulled changes are not pushed back unless this device has newer ones. Storage errors (quota, write rate) show in the status and are retried with backoff
- Sources and occurrences stay on the device. JSON export/import moves all data

### When the browser is not signed in / sync is off
- `storage.sync` does not fail; it just stores locally (behaves like `storage.local`). The quota still applies, so demotion near the limit works the same
- If the user signs in and turns on sync later, data merges with other devices by per-word update time. Nothing special is needed
- The extension has no reliable way to know whether data reaches other devices (`set()` succeeds once written locally)
  - So the UI never claims "synced"; it shows **only the last saved time and usage**
  - Do not request the permission for checking sign-in (`identity.email`). It adds an install warning and still cannot tell whether sync is on
- Users without sync lose everything when they change devices or remove the extension (removing it also deletes IndexedDB). JSON export is the safeguard, so Settings "Backup file" shows the last export time

To check: whether `launchWebAuthFlow` works without a client secret, and whether publishing needs OAuth consent screen review (if not workable, use `getAuthToken` in Chrome only)
- **Dropbox / OneDrive**: PKCE auth, no client secret or server. Store in the app folder
- **Local folder**: write into a folder such as iCloud Drive via the File System Access API and let that folder sync. **Offered only in browsers that have the API (Chromium)**
- **WebDAV** (Nextcloud etc.): the user enters a URL and credentials

## Interface language
- The extension `i18n` API follows the browser's language and cannot be chosen by the user, so use a small custom mechanism: every UI string goes through `t("key")` with one file per language (`locales/en.json`). Switch with the `uiLocale` setting, default `en`
- Only the store name and description use `_locales/en/messages.json` (the `i18n` API)
- The interface language is a separate setting from the dictionary/translation languages (learning and native)
- Strings containing a browser name ("Chrome sync") are not written into the locale file; insert `BrowserEnv` values with `t("key", { syncName })`

## Browser differences (Firefox and others)
Only the Chrome version is published, but the structure must not need rewriting when other browsers follow.

### Principles
1. Call extension APIs through WXT's `browser` (`wxt/browser`). Never use `chrome.*` directly in code
2. Features that exist only in some browsers always sit behind a part (`TranslationProvider`, `PlatformAdapter`, …) and are **detected by whether the feature exists**, never by browser name or user agent
3. When a feature is missing, hide everything related to it (no grayed-out controls, no permanent "not available in this browser")
4. Strings containing a browser name come from `BrowserEnv`
5. WXT generates the manifest per browser. Firefox gets `browser_specific_settings.gecko.id`, and its background is an event page (`background.scripts`) instead of a service worker
6. Verify only that the Firefox build succeeds (no behavior guarantee, not published)

### What `BrowserEnv` holds
- Browser name and sync name (Chrome sync / Firefox Sync) for UI text
- Features detected where `BrowserEnv` is built (built-in AI, File System Access API). The translator is detected in the UI, where it runs: it never exists in the service worker
- Add a field only when code reads it

## Chrome Web Store requirements (checked 2026-11-09)
No outright blocker. Decisions and requirements:
- **Subtitles (decided)**: keep YouTube and Netflix. Subtitle tracks are processed in memory; what is stored is the sentence in which a saved word appears (as an occurrence) and, while Sentence history is on, the lines that actually played (on the device only). Policy risk: "do not facilitate unauthorized access to content" / copyrighted content. Language Reactor does the same on the store. Prepare a written justification for review
- **Host access (decided)**: keep the content script on all sites (`<all_urls>`), accepting an in-depth review (can take weeks). Write a justification (article highlighting on any page the user reads)
- **Sentence history (decided)**: on by default, as in the mock. Browsing activity may be collected only for a user-facing feature described prominently in the store listing and in the UI, so the listing and Settings must describe it clearly, and it stays on the device
- **Privacy policy (required)**: any extension that handles user data needs a privacy policy URL, even when data stays on the device. Recorded sources (URL, title) and sentences count as user data. Disclose: what is stored locally, that word status goes through the browser's sync, that nothing is sent to the developer. Include the Limited Use compliance statement. Host it somewhere public without a server (e.g. GitHub Pages; this repo is private, so a separate public page is needed)
- **2026 policy update (in force since 2026-08-01)**: data collected must be necessary for the single purpose and prominently disclosed
- **Code**: no remotely hosted code (everything bundled, including the MAIN-world scripts); no obfuscation (minification is fine). Hooking page fetch/XHR/`JSON.parse` is not prohibited but needs a justification
- **Downloaded language data**: data, not code, so allowed. Packs are JSON read with `JSON.parse`, verified against hashes bundled with the extension. The privacy policy names the hosts (jsDelivr, unpkg), says they see the IP address and which packs were fetched, and that no page content or words are sent
- **Single purpose**: "learn vocabulary on the videos and articles you read" — keep every feature framed around it
- **Listing**: icon, screenshots and a description are mandatory; no keyword lists ("YouTube Netflix …"); "works with YouTube and Netflix" wording only, no third-party logos
- **Account**: 2-Step Verification; trader / non-trader declaration (EU DSA) — the user decides before publishing
