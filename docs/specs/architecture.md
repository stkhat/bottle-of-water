# Architecture

MV3 / TypeScript / WXT + Preact, UI inside Shadow DOM. UI behaviour: [ui.md](ui.md); decisions and phases: [design.md](design.md).

## Parts
| Part | Role | Implementation |
|---|---|---|
| `LanguagePack` | Word segmentation (`Intl.Segmenter`), the vocabulary (rule E), base forms, frequency rank, **IPA**, phrase patterns with their own parts of speech and the language's **phrase matcher** (slots, gaps, detect vs select, the particles of phrasal verbs, pronominal verbs, contractions), the accents its capitals leave out, parts of speech, the **names lexicon** and whether the language's capitals mark names ("Names and written case"), the **part-of-speech tagger** with the language's grammar of auxiliaries and participles ("Tags" below) | `en`: inflection table, frequency list, IPA table, phrase list and names lexicon built from kaikki (Wiktionary) and EJDict, tagger trained on UD English-EWT; `es` (kaikki Spanish, Wiktionary Spanish frequency list; parts of speech, lemma order and tagger from UD Spanish AnCora and GSD; names lexicon from kaikki Spanish proper names); `fr` (kaikki French, FrequencyWords' OpenSubtitles list, lemma order and tagger from UD French GSD; elisions split off the word they join, "Elisions" below); `de` (kaikki German, Buchmeier's subtitle list with case kept, lemma order and tagger from UD German GSD; capitalised headwords as words, separable verbs' forms written apart: "German" below) |
| `DictionaryProvider` | Short translation, the hover card's lines (up to three senses shortened like the short translation, pointers followed to the word they name: "Short lines" below; the senses of the word's tagged part of speech first: "Tags" below; computed when an entry is looked up, so packs carry nothing extra), details (meanings by part of speech) and an outline of each headword for rule A1, with the source each term came from | `en→ja`: EJDict-hand (public domain). EJDict has no part-of-speech labels: the data build labels its senses (`en-ja/pos.json`, "Tags" below), so the extension reads no Japanese glosses for them; `es→en`, `fr→en`, `de→en` from kaikki's English glosses; `en→es`, `en→pt` from recipes ("Language data") |
| `TranslationProvider` | Translating one subtitle line / sentence. Several implementations tried in order ("Choosing a translation") | ① the site's translated subtitles (from `PlatformAdapter`) ② the browser's built-in translator (Chrome: Translator API). If neither exists, no translation |
| `ExplanationProvider` (phase 3) | A language model that answers a prompt with JSON: whether it can run (ready / downloadable / downloading / unavailable), its download, a session per prompt with its token count and input budget ("Meaning in context") | Chrome's Prompt API (`LanguageModel`, Gemini Nano). Later the mobile app's native bridge, then the user's own API key. None in Firefox |
| `PlatformAdapter` | Get the video element, fetch and parse subtitle tracks (**including the native-language track**), seek, detect the end, detect navigation; optionally say the page is a vertical short video (subtitle only), and that the player fills the window and can be narrowed for the transcript sidebar | YouTube (watch pages and Shorts) / Netflix |
| `TermStore` | Store and sync terms, sources and occurrences | IndexedDB (Dexie) + `BrowserSyncBackend` + Export/Import |
| `BrowserEnv` | Browser names for UI text and feature detection | Chrome (Firefox values only need to build) |
| `PackSource` / `PackStore` | Where a pack's files come from, as the lock file says. `PackSource` reads a pack from `PackStore`; a pack not on the device fails the request with `packsUnavailable`, and pages wait for `packState`. `PackStore` fetches the lock's files from the mirrors in order, checks each against its SHA-256, keeps them in IndexedDB (`packFiles`, `packVersions`), switches a pack to a new version in one transaction and retries failures (1, 5, 30 min, then every 6 h) | every pack downloaded from npm (`@langle/<pack>`) via jsDelivr, then unpkg; none bundled. The E2E build `check-download` downloads from a local mirror |
| `Classifier` | Classify New / Learning / Known / ignored, match phrases, count unsaved words on a page; with the document's casing, take names out (rule D) and mark words capitalised in a way that counts; with a tagger, check each dictionary phrase against its context ("Phrase precision") and choose an unsaved word's base form and the part of speech its lookup shows first (rules A1, A2) | shared |
| `LookupUI` | Hover card, dictionary window, phrase saving, save all (popup "This page") | shared by text and video UI |

- Code layout (`src/`; tests sit next to their code):
  - `core/`: browser-free logic. `explain/` (meaning in context: the provider interface, prompt, context, answer), `lexicon/` (language packs, dictionaries, definitions, lookup, IPA, lemmas, sense labels and rule A2's `sense-order.ts`), `packs/` (loading, the lock, pack states, pairs), `phrases/`, `subtitles/` (parsers, transcript cards, translation alignment), `sync/` (codec, layout), `tagging/` (the perceptron, the `Tagger` part, English's tagger and grammar in `en.ts`), `text/`, `classify.ts` (statuses, `WordStatus`), `word-sense.ts` (rule A1), `names.ts` (rule D), `settings.ts`, `languages.ts`, `browser-env.ts`, `term-id.ts`, `url.ts`, `util.ts`
  - `background/`: the stores (terms, history, packs, settings, translation cache, explanation cache, `sync/`) and `handlers.ts`
  - `messaging/`: what pages and the background share. `protocol.ts` (every message and wire type), `client.ts` (`send`), `storage.ts` (`watchSettings`, `watchPackState`), `page-protocol.ts` (popup ↔ content script), `pack-status.ts`, `pack-wait.ts`
  - `content/`: runs on web pages. `article/` (`article.ts` wiring `blocks.ts` (the live blocks and their spans), `analysis.ts`, `page-casing.ts`, `words-panel.ts`, over `state.ts`, `cards.ts`, `selection.ts`, `recorder.ts`), `video/` (`session.ts` over `state.ts`, `captions.ts`, `playback.ts`, `recorder.ts`, `cards.ts`; the sites in `youtube/` and `netflix/`, Netflix's control bar in `netflix/control-bar.ts`), `lookup/` (what both share: term lookups, the dictionary panel, the hover intent, the one-change-at-a-time queue, "Mark all"), `words/` (what Words lists share: `summaries.ts`, and `list-meanings.ts`, which translates their meanings, also on the word list page), `translate/` (the Translator API queue), `explain/` (meaning in context: the lines around a sentence, the per-page runner), `wiring.ts`, `shadow-host.ts`
  - `ui/`: components the pages and the on-page UI share. `styles.ts` (colors as `theme.ts` variables, highlight colors, the pages' button), `mount-page.tsx` (what each extension page does at start), `press-away.ts` (Escape or a press elsewhere closes), `icons.tsx`, `LangleMark` (Langle's mark, from `brand/icon.svg`, the toolbar icon's source too), `Switch`, `Segmented`, `Meter`, `RowLabel`, `BrandHeader`; `lookup/` (hover card, dictionary window), `video/` (subtitle, transcript, menu), `backup/`, `packs/`, `format/`
  - `entrypoints/`: the background, the content scripts and the extension pages: `popup/`, `options/` (one component per section in `sections/`), `wordlist/` (`WordList.tsx` over `useWordListData.ts`, `Rows.tsx`, `DetailsPanel.tsx`)
  - `i18n/` (`t("key")`, `locales/`), `check/` (the check build's error log), `testing/` (helpers src tests share)
  - Outside `src/`: `scripts/` (data builds in `data/`, the check build's copy, the CLAUDE.md check), `tests/` (fixtures shared by Vitest and E2E, the manifest test), `e2e/` (Playwright)
- Where things run: a content script's IndexedDB belongs to the page's origin, so `TermStore`, `LanguagePack` and `DictionaryProvider` live in the **background** and content scripts / extension pages talk to it through typed messages. Pack data is read by the background in compact formats that reload quickly when the service worker restarts, from IndexedDB, where the downloaded packs are kept. Translating English definitions runs in the UI (content scripts, extension pages), since the Translator API does not exist in workers; the background keeps the results (`mtCache`)
- The UI on web pages sits in shadow roots: closed in production builds so page scripts cannot read it (it shows sentences kept from other sites), open in the check build and in development so tests and the developer can reach it. It acts only on events the user caused (`isTrusted`), not on events a page script dispatches: each shadow root drops untrusted UI events as they enter it (`guardShadowRoot`, `src/ui/from-user.ts`), and the handlers that open the dictionary or change a word check again
- IPA: EJDict-hand has no pronunciations, so the US IPA is taken from the `sounds` field of kaikki (English Wiktionary) and kept in the `LanguagePack`. Phrases show the IPA of their words joined together. Words without IPA hide the field. It is shown in dictionary style (`dictionaryIpa`): Wiktionary's syllable dots, tie bars, aspiration and diacritics are dropped, and ɹ/ɚ/ɝ/ɫ are written r/ər/ɜːr/l. It is set in Noto Sans where installed, else the system UI font, so every IPA letter comes from one font
- Getting video and text
  - **YouTube:** hook fetch/XHR in the page (MAIN world) and receive the `/api/timedtext` (json3) responses the player itself requests. Shorts have their own player (`#shorts-player`); the adapter goes by the URL and tells the page script which player each call is for
  - **Netflix:** hook `JSON.parse` in the page to read subtitle track URLs from the manifest, then parse TTML/WebVTT. Seek through Netflix's player API
  - Sync with subtitles via `requestVideoFrameCallback` + binary search over cues. Detect the video end with the `ended` event, or for a looping video (Shorts) its first seek from the last second back to the start
  - Code: `src/content/video/youtube/` and `netflix/`, each a MAIN-world `page.ts` (no dependencies), its `messages.ts` and the `adapter.ts` (`PlatformAdapter`). Both talk over `page-channel.ts` (`postMessage` to the page's own origin, shapes checked on both sides); `adapter-kit.ts` and `recent.ts` hold what the adapters share
  - Detect the end of an article with an IntersectionObserver on the last element of the body

## Language data
Research behind these choices (coverage per language, hosting alternatives, review findings): [notes/language-data-research.md](../notes/language-data-research.md).

| Unit | Contents | How many |
|---|---|---|
| Learning-language pack `<L>` | lemmas, frequency, IPA, parts of speech, vocabulary, phrase patterns, names lexicon, contractions, capital-only words and tagger model (`en` only so far) | one per learning language, shared by every native language |
| Pair dictionary `<L>-<N>` | words and phrases under the same keys (a phrase's key is its pattern, e.g. `make up one's mind`), one source tag per term | one per pair |
| English definitions `<L>-en` (`en-defs`, `es-en`) | Wiktionary's English definitions of L's words and phrases | the pair dictionary when N = en, the last fallback otherwise |

- Pair pack format (`<L>-<N>/dict-<n>.json` + `capital.json` + `index.json`, format 3): `{ term: [short, [pos, text, hint?, target?][], source] }`; `source` indexes `index.json`'s `sources`, `hint` is a translation table's English sense or a wordnet synset's English definition; a pointer sense (an edition's form of another word) has a null `hint` and names its `target` term ("Edition forms" below). The capitalised headwords are kept apart in `capital.json`, listed first in `index.json`'s shards, under their key with the first letter capitalised, or in capitals for an acronym (`capitalKey`: "Japan", "I'm", "TV", "WHO"), each with what its meaning is as a fourth item ("name", "word", or none; "Names and written case"). `en-ja` keeps EJDict's format, with EJDict's capitalised headwords apart in `capital.json` ("Names and written case"), joined there by the translation tables' Japanese for capital-only words (format 5, "Vocabulary and frequency") and its senses' parts of speech in `pos.json` ("Tags"); its `phrases.json` (the translation tables' phrases) carries its senses' parts of speech as a third item ("Phrase data"). Every file stays under 4 MB (AMO rejects text files over 5 MB)
- French lemma table (`fr/lemmas/`, `fr` format 1, 2026-11-19, L1-1): the same, 196,045 forms in 3 shards (4.8 MB)
- German lemma table (`de/lemmas/`, `de` format 1, 2026-11-20, L2-1): the same, 138,748 forms in 3 shards (4.1 MB), with capitalised headwords' forms ("Häuser" → haus) and a separable verb's forms written apart after their other bases ("fängt" → fangen, anfangen, …)
- Spanish lemma table (`es/lemmas/dict-<n>.json` + `index.json`, `es` format 3, 2026-11-19): every kaikki form of the vocabulary (~380,000 forms, 9.9 MB) is sharded like a dictionary; the loader keeps the shards apart (`LemmaShards`) and a lookup tries each in turn, since merging them into one object would cost more than reading them (Node: ~60 ms to parse, ~60–110 ms more to merge)

### Distribution
- No pack is bundled (user, 2026-11-18): every pack is downloaded, so a user carries only the packs of the pairs they chose (en→ja: about 35 MB raw, 9 MB gzipped on the wire; es→en 16.7 MB raw, 2.8 MB gzipped; fr→en 11.9 MB raw, 2.3 MB gzipped; de→en 11.1 MB raw, 2.3 MB gzipped). Each offered pair's packs stay at most 40 MB raw and each file under 4 MB (`pack-sizes.test.ts`); `en-defs` grows as English pairs are added, up to 28.5 MB, which would take en→ja over (measures and options: [data-sizes](../notes/data-sizes.md) "More English pairs"). With ru, fr and de (D2) it is 21.19 MB; with zh, it and pl (D3) 21.97 MB and en→ja 36.23 MB, the largest pair
- A lock file bundled with the extension (`src/core/packs/packs.lock.json`, written by `npm run data:publish`) lists per pack its npm package, version, data `format` and its files with size and SHA-256, plus the mirrors and the offered pairs. Data fixes ship with an extension release
- Packs: one npm package per pack (published from this repository by `packs.yml`, no public data repository), fetched from jsDelivr, then unpkg (both `Access-Control-Allow-Origin: *`, so no host permissions). Each file is checked against the lock's SHA-256 and stored in IndexedDB, one row per file (`packFiles`, `packVersions`). A new version is fetched beside the old one (stored hashes are skipped), switched in one transaction, then unreferenced files are deleted. A download stopped with the service worker resumes; retries go through `alarms` (1, 5, 30 min, then every 6 h)
- Fetched on install (below), when a pair is chosen in Settings, when synced settings name a pair whose packs are missing, and when the lock changes. A stored version in an older `format` is not used. Packs of a pair no longer chosen stay until removed in Settings
- **First pair** (on install, `runtime.onInstalled` with reason `install`; `firstPair` in `core/languages.ts`): the browser's UI language (`i18n.getUILanguage()`, primary subtag) is taken for the user's own language: the first offered pair with it as the native language, the default learning language (English) before the others (ja → en→ja, es → en→es, pt → en→pt, ru → en→ru, fr → en→fr, de → en→de, zh → en→zh, it → en→it, pl → en→pl, en → es→en; every Chinese UI, zh-TW and zh-HK too, gets en→zh, written in simplified characters); the default pair en→ja when no offered pair has it. It is stored only when no settings are (settings browser sync brings from another device win, and their pair is downloaded when they arrive), and its packs are downloaded at once. A worker start with no settings stored downloads nothing (onInstalled chooses the pair first); an update with none stored stores the default pair it has used
- Without the data: requests that need a missing pack fail with `packsUnavailable`; the packs' state lives in `storage.local` (`packState`), which pages, the popup and Settings watch (the mock's `LanguageData` states, also during the first download), and pages analyze again once it is ready. Offline, the first download fails and is retried like any other
- **Order and readiness** (2026-11-18): a pair's packs download one after another in the order pages need them (`packsFor`): the learning language's pack, the pair's dictionary, then its fallbacks (`fallbacksOf`: a definitions pack written in another language than the native one, `en-defs` for every English pair; `es-en`, `fr-en` and `de-en` are Spanish, French and German → English themselves). Pages analyze and hovers show once the packs before the fallbacks are there: a dictionary is built without a fallback that is not on the device yet, and answers a term only the fallback could have with `packsUnavailable` naming it, so that card (a hover card, the dictionary window, selected words' card) waits and shows once it arrives (`showWhenReady`); rules A1 and D read what is on the device meanwhile. A list request with such a term (the Words tab, the word list) waits for the fallback as a whole, showing its rows without meanings meanwhile. The popup and the video column show the download only until pages can use the data (a failed fallback still shows "Couldn't download"); Settings shows the pair downloading until every pack is there. Files of a pack still to come in a run are kept when the pack before it switches, so a stopped download carries on. First use of English → Japanese in E2E, through one throttled link (gzipped sizes): at 10 Mbit/s the first highlight comes after 4.9 s instead of 9.1 s; at 3 Mbit/s after 12.9 s instead of 26.2 s ([data-sizes](../notes/data-sizes.md) "First use")
- **Hosting** (user, 2026-11-11; live 2026-11-18; every pack since 2026-11-18, D0): all packs are downloaded from the npm packages `@langle/<pack>`. E2E routes the lock's mirrors to `data/packs/` (`e2e/pack-mirrors.ts`); the E2E build `check-download` downloads from a local mirror it can break

### Native meanings and the quality gate
- Each pair has a build recipe (`scripts/data/recipes/`) merging sources in order; **per term, the first source that has it supplies all of it**: a bilingual dictionary (EJDict for en→ja), the native language's Wiktionary edition, English Wiktionary's translation tables, then Open Multilingual Wordnet (OMW 1.4) wordnets. No pivoting through English words at build time. A recipe (`recipes/recipes.ts`) names the edition (none when the tables pass the gate alone), the tables' language codes and the wordnets, each wordnet a source of its own
- **Edition forms** (U1-2, 2026-11-18; `readEdition`): an edition's senses for forms of other words are kept as pointers (format 2) instead of dropped, so told, has, did get entries. Each edition's own pointer syntax is learned from the senses it marks as forms or variants (kaikki's `form-of`/`alt-of` tags or `form_of`/`alt_of` fields): the gloss with its target replaced (at each place it is written: pt "passado simples do verbo do") is a template ("pasado simple del verbo {x}", "{x} 的複數"), kept when it has at least 3 distinct targets, not all of them words of the edition's own language (Wikisłownik's form_of links the Polish word of "me", "him", "us": "po than lub as: ja", on, my). A sense whose gloss is such a template, with an English term it writes in the slot, is a pointer to that term, marked or not (es writes "Pasado simple del verbo (to) see" unmarked); a marked sense that fits no template is left out as before (pl "he is → on jest", whose form_of names jest). A marked form's target is the word kaikki records when the gloss writes it ("to have" → have), none when that is an English phrase Langle has no term for, else the last term the gloss writes (pt's form_of "particípio"). Templates learned per edition: es 8, pt 42, ru 6, fr 54, de 13, zh 56, it 19, pl 24 (pointer senses in the packs: es 778, pt 316, ru 80, fr 2,347, de 2,178, zh 850, it 516, pl 1,494)
- **Edition hygiene** (U1-7, 2026-11-19; NATIVE and PAIR, `readEdition`, every edition): what an edition writes that is no meaning, learned from the edition itself:
  - Pointer syntax it does not mark: besides the templates of its marked forms, a template that its unmarked senses write with three distinct English targets or more (no words of the edition's language, written in lower case: a capitalised one is a name's), that its target ends, and whose words are the edition's own and no English terms ("grafía alternativa de {x}", es armor; ru "вариант {x}", been → bean; fr "→ voir {x}"; it "variante di {x}"; not "american {x} association"). Then a sense is a pointer when its gloss, or its first item that the rest qualifies (pt might: "pretérito perfeito do verbo may, indicando possibilidade"), is a template, or is said in the templates' words (two or more of them, and at most one other word of the edition's own: es wore "pasado simple de wear", fr might "prétérit du verbe auxiliaire may", it labor "variante statunitense di labour"; one clause, a target the gloss writes in lower case and that is no word of the edition's: es you's "…singular y plural" names no "plural"). A contraction's senses keep the marked templates only (contractions show as `contractions.ts` says). Templates learned unmarked: es 25, pt 12, ru 7, fr 26, de 1, zh 0, it 9, pl 3
  - A pointer sense with no part of speech (kaikki's "unknown") takes the word's main one in English (en/pos.json), as the hover follows a pointer in its sense's part of speech: de could ("Präteritum des Hilfsverbs can") → können, not Blechdose (a tin can)
  - Placeholders: a gloss written alike (notes and closing marks aside) under CLASS_HEADWORDS headwords or more whose main item describes (more than three words) and is no word of the edition is left out of lowercase terms (fr "Définition manquante ou à compléter. (Ajouter)": 318 glosses); capitalised headwords leave repeated glosses out as classes. A gloss with no letter ("[[]]") is none; a gloss is cut where another paragraph starts (ru "…\n\nЭто болванка статьи…", "this is a stub")
  - Labels: a lower-case word with a period that opens the glosses of ten headwords or more, is no word of the edition without its period, is followed by native text (not pl "zob.", see) and opens no template (not ru "сокр. от {x}") is a label abbreviation; the build puts it in brackets ("истор. Британия" → "(истор.) Британия"), so the line leaves it out (`editionLine`) instead of ending at it as at a sentence (ru: 31 labels, 7,945 glosses). U1-8: a label goes on over what follows it as one, a one-letter abbreviation or one of the edition's abbreviations ("мн. ч.", plural: "(мн. ч.) слова песни" → слова песни, also after a bracket the edition wrote, "(мн.) ч."), and labels a comma joins (ru mom "амер., канадск., разг. мама" → мама)
  - Abbreviations (U1-8, `withAbbreviations`): a lower-case word with a period that a space follows in the glosses of ten headwords or more, that is no word of the edition without its period and no English term, is an abbreviation of the edition (de "bzw.", pl "itp.", "zob.", "zwł.", ru "сокр.", "тж.", "напр." and its labels; es, pt, fr, zh, it none); the build writes a no-break space after each, and a line's first sentence does not end at a period a no-break space follows (de frippery: "unnötiger Gegenstand bzw. Ergänzung …; Firlefanz" was cut to "unnötiger Gegenstand bzw")
  - A reference that closes a gloss after an arrow, a template with English words in its slot, is cut ("doge → voir duke" → doge; fr seat "voir seat of a car et car seat")
  - A gloss whose first sentence is about the English word, naming it last ("Superlatif de soon", "Variante de prismatic", pl "I don't know"), and whose next sentence translates (no English, a line that does not describe) has the translation first ("Le plus tôt. Superlatif de soon."), as the line is a gloss's first sentence; es we're ("Contracción de we are. Nosotros somos o nosotros estamos") stays, as its translation of five words describes by the three-word rule. A form the edition marks (form-of) whose gloss is reshaped so is a meaning, not a form left out for want of a template (U1-9: fr I’m, "Variante de I am. Je suis." → je suis, was the tables' informal "chuis"), and a headword written with a typographic apostrophe is the vocabulary's word (Wiktionnaire titles "I’m", "we’re": nous sommes, "there’s": il y a). A gloss that points to its own headword is none (pt "you’re": "grafia alternativa de you're"). A contraction comes from a later source that translates what it is short for (en/contractions.json; a table sense "do not") when the former does not (fr don't: the tables' "ne… pas", not Wiktionnaire's "Signifie l’impératif négatif")
- **A term that only points** (every sense of it a pointer in its source) comes whole from the first later source in the recipe that has a meaning for it, and stays with its pointers when none has (pt "used": the edition's "passado … do verbo use" yields to the tables' usado, acostumado); a term with one meaning in a source is that source's whole term, its pointers included. One source per term still holds. U1-8 (`isOtherWord`, LEARNING): it keeps its pointers when the later source's term is another word of the same spelling: none of its meanings is of a part of speech the form can be (its pointers', or what English uses a form of its kind as, by the tags of English Wiktionary's form-of senses: a past participle an adjective, a present participle or gerund an adjective or a noun, a plural a noun, a degree an adjective or adverb; a simple past nothing), and the tables translate it into fewer than a fifth of the languages its base's most translated sense reaches. es dug → dig's cavar, not the tables' "teta" (a teat, 7 languages); fr, pl came; pl sent (not the Estonian cent); it needs (not the adverb "irreparabilmente"); es rats; fr blinder. Not stranger (a noun, 55 languages against strange's 109) or the accused (44 against 63): widely translated, they are words of their own. Not traveling: a gerund can be a noun, so the tables' basketball foul ("dobles") still stands for an untagged "traveling"
- **A term with no meaning in its main part of speech** (U1-6, 2026-11-19; `mergeSources`) comes whole from the first later source that has one: the main part of speech is that of the term's most translated table sense, when English Wiktionary lists it first too (en/pos.json; not for forms, whose only table may be a noun's: es dug → "teta"), an open class; a pointer or an unmarked degree (`degreeOf`) is no meaning of its own; not when the term already gives that translation under another label (yesterday: "ayer" an adverb in the edition, a noun in the tables). fr/pl better (the editions' verb and noun) → meilleur, lepszy; es better ("comparativo irregular de good") → mejor; fr can → pouvoir, run → courir. Terms: es 73, pt 85, fr 107, pl 135
- **Translation tables' sense order** (U1-6; `readTranslationTables`): a term's senses in the order of how many languages translate each (file order among equals), capped after that, not in the page's order: "be" led with its passive auxiliary's table (de werden on is, was, are), "English" lost the language to a size of type (de Mittel) and a surname's transliteration (ru Инглиш). A sense English Wiktionary labels outside standard use (dated, rare, slang, vulgar, offensive, derogatory, dialectal, nonstandard, euphemistic, obsolete, archaic, misspelling; or a table labelled so, "slang: have sex with") comes after the others; not left out of a lowercase term, as kaikki's tags are noisy ("folk", "broil" come tagged archaic, obsolete). A word that translates three or more of a term's senses, more than the first sense's first word does, leads (`withSharedFirst`; zh be: 是 before 在 of "to occupy a place"; de it: es before the first of "er, sie, es"). Words with unexpanded templates ("{{t+|…}}") are left out, and so are the words of a row whose note gives an example of the headword and its translation ("we would sit by the hole… - Winters saßen wir…": its words are the example's pieces, "In the winters", "er sei sofort wieder da."; U1-7). A term whose most translated sense the language says with no word (its row is only a note: "the", article, "not used in Mandarin") is left to the next source, as its other senses are no meaning of it (zh the was 越……越……, "the + comparative", on 6,383 tokens; now the zh edition's "用于名词片语或单个名词前", "定冠词…"; pl the: the edition's "stosowany przed wyrazem znanym z kontekstu" instead of "ten", this; ru can't: the edition's "не иметь возможности"); a lesser sense said so is only left out (U1-9; terms left: es 23, pt 7, ru 202, fr 26, de 26, zh 78, it 7, pl 43)

- **The native side of the glosses** (U1-4, 2026-11-19; NATIVE, `recipe.ts`):
  - Case (`inNativeCase`): Wikcionario and Wiktionnaire capitalise every gloss ("Ser", "Y", "Adquirir").   - Script (`keepNativeScript`, `NativeLanguage.scripts`): in a native language not written in Latin letters, a table word or edition gloss with no letter of its script is left out beside ones that have one (en-zh be: "or implied", a table's parse artifact, beside 是; ru would: "We sat on the bench, опоздает ли автобус" keeps its Russian part); a word that is the headword stays (zh "DNA"), and a term with nothing in the script keeps what it has (ru "that's": "that is", "that has"). Left out: ru 19, zh 70
  - **A closed-class term an edition only describes** comes whole from the first later source that translates it, as a term that only points does (`mergeSources`): every sense that is no pointer is of a closed class (pronoun, determiner, article, preposition, postposition, conjunction, particle) and its line describes (`describes`), and the later source has a sense of one of those parts of speech that does not describe. pl "the": "stosowany przed wyrazem znanym z kontekstu" ("used before a word known from the context") → the tables' "ten"; pl "a" stays (the tables have only the letter). - **Wordnets** (`recipes/omw.ts`, D1 2026-11-18): the English wordnet (`omw-en`, Princeton WordNet 3.0) files each English lemma's senses under the pack's term keys (the tables' `termKeyOf`: lowercase vocabulary words and phrase patterns), and a synset's offset links it to the native wordnet's synset. Per sense whose synset has native lemmas: those lemmas, the sense's part of speech, and the synset's English definition up to its first ";" as the hint (as the tables' English sense). Main senses first: each part of speech's first sense (WordNet orders a lemma's senses by frequency), then each one's second, and so on, the parts of speech by WordNet's tagged counts; at most 4 senses, like the tables. - Wordnet lemmas: a "+" join is closed up ("婚姻+的" → 婚姻的), notes in brackets and underscores are dropped; what is left must be words (letters, digits, inner apostrophes, hyphens, periods) with a letter: lists ("c / c"), descriptions with commas, markers ("GAP!"), acronyms (no lower-case letter in a cased script: "V", "A.F.") and one-letter symbols ("s" for a second) are dropped. ### Adding a native language
Everything the extension does differently per native language is one entry in `src/core/natives.ts` (`NATIVE_LANGUAGES`): its names (message keys), whether it is written with spaces (joined subtitle lines), whether its script is dense like Chinese characters and kana (meaning lines capped at 25 wide characters instead of 40, in the hover's translated line and the meaning-in-context prompt), the prompt's example answers (or none: English's), and `englishPair`, the data format of its recipe pair pack. The pack formats, `DICTIONARY_PACKS`, the pack loaders, the background's dictionaries, the language menus, the prompt and the line joins read it. Japanese-specific grammar stays where it is (EJDict's pack and sense labels, `japaneseTranslation`'s clause cuts), and so does what is per learning language (speech voices, names by case, the language packs). For an English → N pair:
1. `NATIVE_LANGUAGES`: N's entry with `englishPair: { format: 3 }`, and its names in `src/i18n/locales/en.json` (`language.N` "Name (Endonym)", `languageName.N`)
2. `scripts/data/recipes/recipes.ts`: N's recipe (the typecheck asks for one): an edition (first, or `afterTables` when a blind sample prefers the tables' words: measure the gate with the tables alone, the edition first and the tables first, and judge both orders on the corpus, as for ru, fr and de in "Native meanings and the quality gate"), the tables' language codes (and `langs`, kaikki's names of the rows to keep, for a language whose tables nest varieties: "Chinese Mandarin"), wordnets, `simplified` for Chinese; every source tag needs its source in `scripts/data/formats.ts` (`RECIPE_SOURCES`, with authors and a license from `LICENSES`; a new WordNet-style license brings its notice into `scripts/data/licenses/`)
3. Download the raw files (development.md "Language data"), then `npm run data:native -- N`, `npm run data:en-defs` (en-defs keeps the terms some English pair lacks, so it grows) and `npm run data:stats`: the pair must pass the gate
4. `npm run data:publish` (the lock offers the pair once it passes); `pack-sizes.test.ts` keeps the pair's download within 40 MB
5. `THIRD_PARTY_NOTICES.md` names the new sources (the extension's data sources and licenses page lists them from `scripts/data/formats.ts` by itself; About stays one line); a test pack in `src/testing/packs.ts` where tests need the pair

### Phrase patterns
- A pattern is words and slots (`one's`, `someone`, `something`, `oneself`; Spanish `alguien`, `algo`) with flags `detect` (automatic highlighting) and `gap` (words may come between parts, as in phrasal verbs). A pattern's word matches a token's written form or any base form, so keys keep Wiktionary's wording
- Each language's phrase matcher (`LanguagePack`) fills slots (English possessives → `one's`, object pronouns → `someone` / `something`, reflexives → `oneself`) and applies the gap rule
- **Pronominal verbs** (CORE mechanism, LEARNING `PhraseRules.reflexive`; Spanish, 2026-11-19, step U2-6 of [spanish-quality](../notes/spanish-quality.md)): a pattern writes the verb with its reflexive pronoun attached to the infinitive (`darse cuenta`). It matches a form with a reflexive pronoun attached ("darme cuenta", "dándose cuenta", "date cuenta": an infinitive or a gerund takes any person, an imperative only its own, and one of more than one syllable writes its stress, so "dame" and the past subjunctive "llevase" are no reflexive forms) and a finite form or participle after a reflexive pronoun (me, te, se, nos, os), which joins the match as its `lead` ("me di cuenta"; up to two other pronouns or forms of haber or estar between, which are a gap: "se lo tomó", "se ha quitado la vida"). Where a pronominal verb's pattern matches a form with the pronoun attached, the plain verb's patterns starting there do not ("darse cuenta de" is `darse cuenta`, not `dar cuenta de`); a plain verb with another pronoun keeps them ("darle cuenta de", "le di cuenta de")
- **Elisions** (LEARNING `ELISIONS` in `text/tokenize.ts`; French, 2026-11-19, step L1-1): the segmenter keeps "l'homme" one word; the tokenizer splits the language's elided words off the word they join (French l', d', j', m', t', s', c', n', qu', jusqu', lorsqu', puisqu', quoiqu', with ' or ’), unless the language pack knows the whole as a word of its own ("d'accord", "aujourd'hui", "s'agit": "Words written with an elision"), checked again on what is left ("qu'aujourd'hui" → qu', aujourd'hui). Each part is a token with its own offsets and no space between, so it is classified and hovered alone ("l'" → the). Casing reads every elision apart. In keys an elided word is joined to the next by nothing, as text writes it (`separatorKey`: "avoir l'air", a selection of "l'homme" saved as `l'homme`), and a key's words are split as text is (`splitKey` with the words the tokenizer reads whole, `PhraseMatcher.keyParts`: "avoir l'air" is avoir, l', air; "mettre d'accord" mettre, d'accord), wherever a match's words are read against its key's (2026-11-20, L1-4)
- **Hyphenated compounds** (CORE, `tokenize`'s `joinCompounds`; 2026-11-20, L1-4): hyphens split words, except a run of words joined by single hyphens that the pack knows as one word, the longest such run ("peut-être", "c'est-à-dire", "là-bas"; English "well-known", "long-term", "x-rays"), in every language. Which compounds the pack knows is the learning build's: French keeps those UD French GSD writes as one token in half their occurrences at least ("est-ce", "a-t-il" are split there: the verb and its subject pronoun read apart); English has kaikki's hyphenated headwords; Spanish none. A compound the frequency list does not rank ranks as its rarest part ("well-known": known)
- **French pronominal verbs** (CORE mechanism, LEARNING `ReflexiveRules.leading`; 2026-11-20, L1-4): a pattern writes the pronoun as a word of its own before the infinitive ("se rendre compte", "s'en aller"). Text has any reflexive pronoun there, which stands for the pattern's: être's forms right after it (and its object pronouns before them) are left out as a gap ("je me suis rendu compte", "il s'en est allé", "s'être rendu compte"), and me, te, nous, vous count only with their own subject within four words before (`ReflexiveRules.subjects`: "nous nous rendons compte"; "ça me fait plaisir" and "nous rendons compte" are no pronominal verb); or the pronoun follows an imperative and a hyphen (`after`: "rends-toi compte"). The match has the pronoun among its words, in text order
- **German word order** (CORE mechanism `PhraseRules.verbLast`, matcher `verbLastAt`; LEARNING `GERMAN_RULES.verbLast`; 2026-11-20, L2-3): German Wiktionary writes a verb pattern with its verb last, in the infinitive ("in Kauf nehmen", "sich auf den Weg machen"), as text has it after a modal or in a verb-final clause, also with "zu" before the infinitive ("in Kauf zu nehmen"). In a main clause the finite verb comes second or first and the pattern's other words at the clause's end: a verb pattern (its parts of speech name a verb) whose verb is a form of word i, standing before its other words in the clause with at most four words between (none a conjunction or subordinator, `gapStop`), matches with word i as its `lead` and `PhraseMatch.moved` ("Er nimmt das gern in Kauf", "spielt keine Rolle", "weiß das zu schätzen"); a separable verb's particle comes right after the others ("gibt den Löffel ab" for `den löffel abgeben`: the verb's form is a form of the verb it is made of). The pattern's "sich" is any reflexive pronoun that agrees with the subject in its clause (`pronouns`: sich always, mich and mir with ich, dich and dir with du, uns with wir, euch with ihr; "er macht mich" is no `sich … machen`), with words between it and the others ("macht sich endlich auf den Weg"). A separable verb the lemma table lists among a simple verb's bases ("hört": aufhören, for "hört … auf") is a literal only joined ("aufhören"); written apart it matches only as a moved verb with its particle ("lass mal gehen" is no `mitgehen lassen`). A moved verb must be read as a verb (its tag, else the grammar). The words in a phrase's gap are classified as phrases too, each one that starts and ends there ("nimmt zum Beispiel das in Kauf")
- **Negation inside a phrase** (CORE mechanism `PhraseRules.negation`, LEARNING `FRENCH_NEGATION`; R3, 2026-11-20): French writes its negation around the verb ("ne … pas"). The negation's second word (pas, plus, jamais, point, guère, rien) may stand inside a verb pattern (its parts of speech name a verb), right after one of its words that "ne" or "n'" comes before (within four words, joined), and is a gap: "je ne me rends pas compte", "je ne me suis jamais rendu compte" (`se rendre compte`), "il n'a pas l'air" (`avoir l'air`). "pas" and "jamais", which negate alone in speech, need no "ne" ("j'ai pas envie", `avoir envie`); "plus" and "rien" without it are "more" and an object. Not in a pattern that holds "ne" itself ("ne fait pas qu'aider" is no `ne faire que`) nor in one that is no verb's ("c'est pas ça" is no `c'est ça`, "that's right"). Spanish ("no" before the verb), German and English have none
- **Contractions** (LEARNING `PhraseRules.contractions`; Spanish al = a + el, del = de + el; French au, aux = à + le/les, du, des = de + le/les; German am, ans = an + dem/das, im, ins = in + dem/das, zum, zur = zu + dem/der, beim = bei + dem, vom = von + dem): a contraction stands for its preposition only as a pattern's last word, where the article opens what follows ("a través del tiempo" is `a través de`, "frente al", "a partir del"); inside a pattern the article would be missing from it ("al tiempo" is no `a tiempo`, "al fondo" no `a fondo`)
- Detect mode (highlighting): contiguous `detect` patterns without slots; saved phrases also match with slots and gaps. Saved phrases are placed first, the longest first (words from first to last, gap words included; then the most pattern words, the earliest start, the key), each where it overlaps no phrase placed before it, so a phrase saved over part of a shorter saved one is drawn and, of two the same length, the earlier one; detected phrases fill only the words outside them, so a saved phrase wins over a detected one even when the detected one starts earlier or is longer
- Select mode (a selection, `PhraseMatcher.matchSelection`): every pattern, but only one whose first-to-last word (gap words included) spans every selected word and has at least two of its words selected; among those the most pattern words win. The sentence decides when the selection is part of a longer pattern ("made up" → `make up one's mind`, "made it up" → `make up`); a selection that reaches past a pattern, or holds a shorter one, is its own words ("gave up the crust" → "give up the crust")
- A phrase with a gap becomes one span per contiguous part (same key, part number); words in the gap keep their own spans. A phrase span whose key has a slot another word fills is marked `slot`. A selection is saved under its pattern's key, else under its words' keys
- Snapping a selection (`core/selection.ts`): to whole words; a detected phrase, and a contiguous saved phrase the selection covers only part of, count as their words (the key's word for each); a saved phrase the selection covers whole, one with a `slot` and every part of a phrase with a gap widen the selection to the whole phrase
- **Phrase parts of speech** (LEARNING data, `PhrasePatterns.pos` in `en/phrases.json`, `phrases/phrase-pos.ts`): each pattern's own parts of speech in kaikki (verb, adv, prep_phrase, intj, particle, phrase, noun, adj…), the one with the most usable senses first, one letter code per pattern of `detect` and of `more` ("vi": a verb, then an interjection); 72,013 of 73,112 patterns have one (EJDict's alone have none). `intransitive` lists the verb patterns with a sense kaikki marks intransitive and none marked transitive or naming someone / something in its gloss: 1,001, weak data, read by one rule only

### Phrase data (rules B1, B2, B2b, B4, C1, C2)
Built by `scripts/data/phrases.ts` (patterns, Japanese phrase meanings) and `scripts/data/en-defs.ts` (English definitions); every rule reads the source's own structure and statistics, never a list of phrases. Layers: CORE (`idiomaticity.ts`, `senses.ts`, `examples.ts`), LEARNING (`PhraseLanguage`: which kaikki parts of speech are discourse, nominal, content, names; slots, auxiliaries), GLOSS (English glosses: usage and literal notes; stopwords are the source's own most frequent gloss tokens), NATIVE (`NativeGlosses`: Japanese content units are kanji and katakana runs; a katakana-only gloss is a loanword), PAIR (EJDict, the translation tables)
- **B1, every multi-word entry**: each kaikki entry with a sense of its own (not form-of / alt-of, obsolete, archaic, a misspelling, a literal note — "Used other than figuratively or idiomatically", since L2-3 also "for non-idiomatic uses see …", "non-idiomatic combination of …" — or a non-constituent) whose words are vocabulary words, their inflected forms or possessives ("for God's sake"), at any word rank, plus EJDict's multi-word headwords. A multi-word noun or name needs a translation table or an occurrence in the example corpus (44,785 unattested compounds left out). 73,112 patterns (19,932 before): 28,482 `detect`, 44,630 `more`, 4,726 with a gap; all matchable on selection
- **Example corpus** (`examples.ts`): every usage example and quotation of the extract with the entry's own headword cut out where kaikki marks it in bold (English: ~21 million tokens); counts each pattern's words as written or inflected, a key as written for itself first (L2-3: German "nach Hause" counted for the alt-of `nach haus`, Hause being a form of Haus, left `nach hause` with none)
- **B2, idiomaticity** (replaces the rank rules of 2026-11-11): score = Σ wᵢ·opacityᵢ / (Σ wᵢ + 0.3·log10(1 + count) + literal note). A sense's opacity is 1 − the share of its gloss tokens found in its words' own first glosses (at least 0.9 when the source tags it idiomatic or figurative, or for a discourse pattern: interjection, phrase, particle); its weight is √(1 + translation-table languages) × 0.9^rank × e^(−0.5 × label penalty) (rule C2's labels, usage notes aside). For a content pattern with a Japanese gloss, 30% of the score is 1 − the share of its kanji/katakana found in its words' EJDict glosses. Detected when score ≥ 0.55 + 0.03·log10(1 + count) + 0.1·max(0, 3.5 − PMI), PMI being log2 of observed over expected co-occurrence in the example corpus. A fixed expression (R3, 2026-11-20; LEARNING data `PhraseBuildLanguage.fixed`, Spanish): a pattern the language's treebanks write as one UD `fixed` expression at least 5 times and at least as often as not where its words stand in a row (`fixedExpressions`: "sin embargo" 340 of 346, "a pesar de" 184 of 184, "al menos" 53 of 91; the treebanks annotate unevenly) has no literal reading: neither the score's literal term nor the threshold's count term (12 more Spanish patterns detected: sin embargo, al menos, a pesar de, de nuevo, al contrario, por el contrario, por último, siempre que, sí que, un tanto, al respecto, a muerte). French and German supply none yet. Never detected: slot patterns, patterns starting with be / have / do. The source's phrasal verbs (its "phrasal verbs" categories) are detected whatever their score: a verb and particle's gloss overlaps its verb's long sense list ("come back" → "To return"), and P2 ("Phrase precision") checks each match. Patterns under the threshold stay in `more`

### Phrase precision (detect mode)
Precision before recall (user, 2026-11-13). Every rule is grammar or the source's own labels, never a list of phrases. At each word the longest dictionary match decides; when it breaks a rule, no dictionary phrase starts there (a shorter one does not stand in: "so long as" is no "so long") and its words are classified as words, with their tags (A1, A2, D). Saved phrases and selections are not checked. `core/phrases/fit.ts` (`phraseMisfit`, CORE) reads the pattern's parts of speech, its words' main parts of speech (`LanguagePack.partsOfSpeech`), the language's particles (`PhraseRules.particles`) and each word's tag and closed class from the tagger (`Tagger.role`: determiner, noun-phrase start, object, modal or do-auxiliary, infinitive marker, preposition, subject, partitive, be, past participle). Without a tagger only P1 applies
- **P1, utterances**: a pattern whose only part of speech in the source is "phrase" (a whole utterance: "to be honest", "what's up") is never highlighted; it stays available to selections
- **P2, adverbial particle**: a two-word verb pattern ending in a particle is highlighted only where the particle's trusted tag is an adverb (RP/RB: "find out", "give up"), or a preposition follows it ("sneak out of here"); "come to" + a place, "talk about", "look at", "fill in the form" are words. An untrusted tag keeps the match, unless the particle is one the language never uses as an adverb (`PhraseRules.prepositions`; English: at, for, from, into, of, onto, to, toward(s), upon, with): "going to try", "went to Broadway"
- **BASE, the base the tag reads** (CORE, `classify.ts`, with a tagger and the dictionary's outlines): a pattern word matched through a base form of an inflected verb with several bases must be the base rule A1 reads the word as: the key it gives, or, when A1 keeps the word's own entry, the base that entry's first sense is a form of ("went": goの過去, so "went on" stays `go on`). Spanish "fue de" is ser, so it is no `ir de` (16 → 4 in the Spanish study). A word A1 reads no base for does not count against the phrase. A word that is mainly a verb itself (with no trusted tag), or tagged as an inflected verb, matched through a base that is no verb is another word (2026-11-20, L2-3: "landen unter" is no `land unter`; English, Spanish and French unchanged). A headword whose trusted tag is a part of speech of its own that the base has none of is no form of the base (2026-11-19: "fuera de", the adverb, is no `ir de`; "de vista", the noun, no `de vestir`; English unchanged). A pronominal verb's word is checked as its plain verb ("di" in "me di cuenta" for `darse cuenta` must read as dar)
- **LONGEST, a longer pattern around it** (CORE): a detected phrase inside a longer pattern that is matched only on selection, contiguous and starting before it, is not highlighted when the longer one is another part of speech (`PhrasePatterns.pos`; or either has none): it is another expression ("de vista" in the noun "punto de vista"; "as well" in the verb "might as well", "my ass" in "kick one's ass", "last time" in "for the last time"). A longer one of a part of speech the phrase also has extends it and leaves it highlighted ("off the bat" in "right off the bat", "of course" in "and of course", "now and then" in "every now and then"). The longer pattern is not highlighted either (it was left to selections); the cost is a part that kept its meaning inside a verb pattern ("good time" in "have a good time").
- **COMPLEMENT, a verb and its complement** (CORE, U1-9): a selection-only verb pattern that is one lexical verb (its word mainly a verb, not a modal or "be") and a pattern of a complement's part of speech right after it (noun, adjective, prepositional phrase) is that verb with its complement: a detected complement stays highlighted inside it ("in love" in "fall in love"), and a detected phrase that would cut across the complement is not highlighted ("fell in love" is no `fall in`, "to enter"; "got in touch" no `get in`). A modal's pattern is not one ("might as well": `as well` stays out), nor an adverb's or an interjection's complement The select trie is built on the first block with a detected phrase (~60 ms for English in Node, ~3 ms for Spanish) instead of on the first selection
- **LITERAL, written words that are a preposition** (CORE, 2026-11-19): a detected phrase that reads a word without a trusted tag as another word's form is not highlighted where the words as written are a prepositional pattern (`prep`, `prep_phrase`) that it is not ("Fuera de Chile": `fuera de`, not `ir de`). A trusted tag is left to BASE; English: no change
- **Pronominal use** (CORE, LEARNING grammar; U2-7; French since L1-4: a verb after an agreeing reflexive pronoun, or a participle after être and one, "il se rend compte", "il s'est rendu compte"): a verb the grammar reads as pronominal from a reflexive pronoun before it (`WordUse.pronominal`: "me fui de vacaciones", "se fueron de campamento", irse) starts no plain verb's detected pattern (`ir de`, to act like); a pronominal verb's pattern, which leads with the pronoun, may ("se le fue de las manos" → `irse de las manos`)
- **FIXED, invariable patterns as written** (CORE, `classify.ts`; 2026-11-20, L1-4): a detected pattern the source has only as an invariable expression (no verb, noun, adjective, name or utterance among its parts of speech: a conjunction, adverb, preposition, interjection) is not highlighted where a word of it is matched through a base form: "ils disent que" is no `dire que` (to think that), "faire mieux" no `faire bien`, English "I saw" no `i see`, "kinds of" no `kind of`, "for better" no `for good`; Spanish "a tiros" no `a tiro`. A contraction for its preposition and an elided spelling ("parce qu'il") count as written
- **Names** (CORE, 2026-11-19): a phrase, saved or detected, has no word the document reads as a name (rule D): "recuerdo al Chile que ya no es" is no `al chile`; English "Joy Division", "Rolling Stone", "London Stock Exchange" lose `joy division`, `rolling stone`, `london stock`
- **Auxiliary** (CORE, 2026-11-20, L1-4): a pattern of two words or more ending in a word the grammar reads as the auxiliary of the verb after it is not that phrase: "ça va être" (it's going to be) is no `ça va` (how are you), "s'en est aperçu" no `s'en être`
- **Determiner** (CORE, 2026-11-20, L1-4): a conjunction, preposition or determiner pattern that opens with a noun, right after a determiner, is that noun's phrase: "l'histoire de Marseille" is no `histoire de` (in order to)
- **Context**, by the pattern's main part of speech; punctuation between the phrase and a neighbour cuts the link:
  - adverb: not after a determiner when a word of it is mainly a noun, unless a verb, adjective or adverb follows ("the first thing we need"); one ending in a preposition not before a personal pronoun, its object ("this isn't just about you", "kind of you"; "just about everyone", "just about done" stay)
  - prepositional phrase: inside a clause (a word before it, no pause), not before a noun phrase ("in advanced talks", "seat D in Green Class"), unless it ends in a preposition; one ending in a determiner or pronoun not before the partitive "of" either ("after all of that"; "as a result of" stays)
  - interjection or particle: not after a modal or do-auxiliary ("do you know"); one not starting with a pronoun also not after a determiner, the infinitive marker or a preposition ("a good day", "for so long"); one starting with a verb not after a subject ("he got it"); one ending in a verb not before an object, in a punctuated document ("you know the guy"); one that is a whole clause with its object, its subject a personal pronoun ("you tell me", "you hear me"), not next to another word of a sentence, in a punctuated document ("why don't you tell me what's going on", "you told me that…"). "don't", "doesn't" and "didn't" count as do-auxiliaries, and "--" as a pause
  - adjective or noun (no verb among its parts of speech): not where a word of it is tagged as a bare verb ("I have to go" is no "to go", 持ち帰り)
  - interjection ending in a form of "be" (`WordRole.be`): not before a word tagged as its complement, a noun, pronoun, determiner, adjective, adverb or numeral ("eso es lo que", "eso es muy peligroso"; "¡Eso es!" stays; 2026-11-19)
  - a possessive determiner and a noun, the source's parts of speech no verb or interjection (a term of address: "mi vida", "mi alma", "my lady"): only standing apart, with punctuation or the block's edge on both sides ("toda mi vida" is words; 2026-11-19)
  - conjunction ending in a free relative, a word read as a determiner and a pronoun ("lo que"), right before a word tagged as a verb: not highlighted, the relative clause is the verb's ("juzgar por lo que ha hecho", by what he has done; "…, por lo que la oposición logra" stays `por lo que`, therefore; "a menos que vengas" has no article and stays; U2-7)
  - in a language whose adjectives follow nouns (LEARNING `PhraseRules.adjectivesAfterNouns`, Spanish): a pattern ending in a noun whose own parts of speech are adverbial, prepositional, adjectival or interjections (its noun stands bare) is not one before an adjective, which makes the noun the head of a longer noun phrase ("al día siguiente", "al aire libre", "a las fuerzas realistas"; a noun pattern stays: "base de datos relacional"; 2026-11-19)
  - verb: not when its first word is tagged as something else after a determiner, an adjective or a number ("take that mask off", "a deadly pile up"; after a subject a noun tag is more often the tagger's mistake: "boyfriend break up"); not a past participle right after "be" whose particle opens a noun phrase ("to be passed up the chain"); not an intransitive pattern whose particle is tagged as a preposition before a determiner or number
- **Discourse markers** (`markerPos`): a phrase the source also has as an interjection or particle, at a clause start (the block's start or after punctuation) and not before an object, gets `pos: "interjection"`, so its lookup shows those senses first (rule A2: "Come along, children" → "Expression of encouragement…" instead of "To accompany"). Sources with labelled senses change: Wiktionary's definitions, the translation tables' phrases (their parts of speech, "Phrase data"), the pair packs, and EJDict's phrases whose patterns have several parts of speech. Over the corpus 923 phrase spans are discourse markers; 186 hovers show other senses first (all right 142: 畏まりました,了解,オーケー before 大丈夫な; shut up, get out, not at all)
- **Punctuation** (`DocumentCasing.unpunctuated`, from the content script's casing pass): a document of at least 50 words with fewer than one comma per 50 is unpunctuated (speech recognition); there a verb-final interjection's object rule is off
- English's particles: about, above, across, after, against, along, apart, around, as, aside, at, away, back, before, behind, below, beneath, beside, between, beyond, by, down, for, forth, from, in, into, of, off, on, onto, out, over, past, round, through, to, together, toward(s), under, up, upon, with, within, without. Spanish has none (P2 is off)

### Transcript cards classified together (R4-asr, 2026-11-20)
A transcript card ends where its sentence does when the track says so, but also where speech recognition only pauses, where YouTube's machine translation ends a sentence the track does not punctuate, and where a long sentence is cut at 30 words. Classified card by card, a phrase across such a break was lost ("sin | embargo" showed embargo's own meaning, "as | soon as"). So the video session classifies the cards as the text they are part of (CORE, `core/subtitles/runs.ts`):
- **Runs** (`runsOn`, `cardRuns`): a card runs on into the next one unless its last line ends a sentence (`SENTENCE_END`), a sound label stands at the break ("[Music]", "lo que [risas]") or the next card opens with a speaker change (">>", a dash) or a ♪. Each request (50 cards) sends each run of cards as one block, joined by a space, with the card before and after the run as context when the sentence runs on from or into them; their spans are dropped. A card's own line breaks become spaces too (layout, no sentence end: judged blind on English YouTube human tracks, 25 : 8 and 17 : 7 on a fresh sample), except before a speaker's dash line, which starts another speaker's sentence. Every character keeps its offset
- **Breaks** (`ClassifyOptions.breaks`, sent as `analyze`'s `breaks`): where the cards meet. Phrases, saved or detected, are matched across them; every other rule reads each card as it would alone: a break ends a sentence for the tagger and the casing rules, and starts a block for the rules that read one ("y bueno" said alone, a word standing alone, rule D's word before). Measured: reading the tags across breaks too changed about 1–3% of the ASR tracks' hovers and was judged no better (61 : 61 over es, fr, de, en; German worse, 14 : 20: the clause's end at a card's end decides separable verbs and the cut-off "zu")
- **Spans back to cards** (`splitRun`): a span inside one card moves to its offsets. A phrase across cards is a part in each card (`Span.part`, numbered across them, its whole phrase clipped to the card, `previous`/`next` where it goes on), so the subtitle line and the transcript card highlight each piece. From either piece the hover card and the window show the whole phrase (`acrossCards`: its words in all cards, the sentence the cards' text), saving records that sentence, it counts once in the Words tab (written as said) and in the occurrences (in the card it starts in), and a selection keeps the piece its card has
- **Measured** (2026-11 corpora, YouTube auto-generated tracks): phrases across cards 1.3 per 1,000 tokens in Spanish, 0.7 in French, 0.4 in German and English (YouTube human tracks without final punctuation: 0.2–0.6; Netflix and articles unchanged), judged blind, units preferred 17 : 4 (es), 23 : 1 (fr), 7 : 2 (de), 25 : 8 (en), the first round agreeing (18 : 3, 25 : 1, 11 : 2, 19 : 14). Classifying costs the same per token (the context cards are one card per request edge). English's wrong matches across a break are mostly a new sentence after a pause ("right | now I'm…"), left ([status](../status.md))

### Definitions translated at display time
- The English definition is translated, not the phrase ("spill the beans" → "To reveal a secret." → 秘密を漏らす). Leading labels are dropped; pointer senses ("Alternative form of …") stay English
- A definition that is only a usage note (`isUsageNote`: "Used to…", "Said…", an apophasis or rhetorical question) is not translated for the hover card, the window's short meaning or the lists: the term as written is, as a phrase no dictionary has ("not to mention" → 言うまでもありません; "you see" → わかります), marked "Machine translation"; the window keeps the definitions. Judged with Chrome's translator over the 22 such terms of the corpus (94 uses): better in 71 uses, worse in 12 (my goodness → 私の良さ, suck it, made you look, oh man, no relation), alike in 11
- For a phrase, a usage note is also a definition that names what the phrase is or does instead of meaning it (2026-11-14, NATIVE: English glosses), read with its sense's part of speech and only for one that is not nominal (a noun's "A word used to…" is its meaning; the nominal labels are `NOMINAL_POS`, the data build's `ENGLISH_PHRASES.nominal`). Three shapes of the gloss head: a head noun phrase followed by a reduced relative clause ("A phrase used at parting", "A greeting said at noon", "Expletive used for emphasis"; "used/said/uttered" followed by a preposition, an -ly adverb, punctuation or the end); a head noun that names a class of expressions by function, after an article or a modifier (the source's own function categories: intensifier, filled pause / filler, hedge, discourse marker, greeting, farewell; or "indication of/that"); "Serves/Functions as …". "An expression of surprise", "An exclamation of greeting" and a bare "Farewell." stay meanings, and pointers stay as written. A word's function label is not one: its literal translation would be the word itself ("gon"), and its first sense is its main one. Measured in docs/notes/translation-quality.md "Function-label definitions"
- The hover card shows a translation as one line (`translatedLine`): each comma item once, no final 。, within the Japanese cap. - The short meaning is translated as the sense it was cut from when it is that sense without its final period (`shortDefinitionText`; 78% of en-defs entries): the window's headline and its Meanings row then show one translation, the headline without its final 。. ### Short lines (the hover card)
`core/lexicon/short-lines.ts` makes each entry's `short` at build time and the hover card's lines when an entry is looked up, one sense per line. The rules are layered so another pair brings only its own parts:
- **Language-independent**: the first sense is the text up to the first sense separator outside brackets. A line is capped by display width (wide characters count 2): a longer one first loses its parenthesized notes ("(…が生れつき備えている)能力,力" → "能力,力"), then is cut at the last comma that fits, else cut hard with "…". Repeated comma items are dropped. A pointer sense stays whole
- **Pointers** (`shortLines`): a sense that only points to another word, a form ("goの過去", "Plural of casa") or a reference ("=anyhow", "Synonym of look for"), is followed one hop to the entry it names, within the same source. A form that is the first sense stays first with its target's first meaning, then the entry's own meanings, then the target's (went → goの過去, go's first two meanings; found → findの過去・過去分詞, find's first meaning, …を創設する). Pointers are followed only from such a first form or from an entry with no meaning of its own: a pointer after the entry's own meanings marks a lesser use ("them": "=those"). A pointer that names several words ("am not, is notの短縮形") or glosses its target ("Synonym of deal with (“to behave …”)") is not followed; one that lists spellings of one word (the same letters apart from case and punctuation: "=OK,O.K.") follows the first (U1-7: okay → 大丈夫な). The target's lines come in rule A2's order ("Tags" below) for the pointer sense's own part of speech, else for the word's tag (told → tell's verb senses before its noun "a tell"; slept → 眠る before 眠り). `short`, the dictionary window and the word list keep the entry as it is
- **Pair pointers** (U1-2, 2026-11-18; CORE mechanism, each edition's syntax learned at build time): a recipe pair keeps its edition's forms as pointer senses that name their target (format 2: `[pos, text, null, target]`), so the hover reads them in every native language without parsing the gloss. Their line is the gloss's first sense without notes in brackets and closing marks, whole ("Pasado simple del verbo tell"). Where a first pointer shows depends on its grammatical kind, the pointer sense's part of speech (2026-11-18, judged blind; presentation left to us by the user, following language-learning practice: meaning first, form second): a verb inflection comes second, after its base's first meaning ("told" → contar, "Pasado simple del verbo tell", relatar), in a spaced script (`NativeLanguage.dense` false); an auxiliary's pointer (`pos` "auxiliary", "Tags" below) comes first and whole, as it is what the word means there ("has been" → "Tercera persona del singular del presente simple de have", haber since U1-9); be as an auxiliary is read as the verb it is (U1-8, below); any other form comes first (best → "Superlativo de good", bueno; children → "Forma del plural de child", niño), and in a dense script (Chinese) a verb inflection too, as Japanese shows its pointers. Except for an auxiliary's, a pointer too wide is left out (`fitsPairCap`, U1-4): one that comes second, a verb inflection, within the native cap (50; judges preferred it shown, pl/es/fr "said": mówić, "forma czasu przeszłego prostego czasownika to say"), one that comes first within 40 (it holds back the meaning: at 50 judges preferred ru "teeth" as зуб alone) while a meaning shows ("is" → ser / estar). Be as an auxiliary (U1-8, 2026-11-19; `WordUse.lexical`, "Tags" below) keeps its meaning, which the native languages say with their own "be", so it is looked up as the verb it is, as the copula is: es "was built" → ser, estar, not the edition's whole pointer first ("primera persona del singular del pasado simple de indicativo del verbo be", 73 wide; judged 13 vs 6), fr "was going" → être, then "troisième personne du prétérit de be" (8 vs 2 against the pointer first). Have, do and get as auxiliaries keep their whole pointer: judged against their verb's meanings, the pointer won (has: "tener", "иметь", 9 vs 4; got: "obter", 3 vs 0). The dictionary window keeps every pointer. Japanese keeps EJDict's pointers as they are. Degrees an edition leaves unmarked are read as pointers at lookup, and a followed form's base meanings come before the word's own of another part of speech ("Tags" below, A2; 2026-11-19). ### Tags: base forms and senses by part of speech (rules A1, A2)
A word's tag in its sentence decides which entry the hover looks up and which senses it shows first. The rules are layered like the short lines; a learning language without a tagger leaves them off and nothing changes:
- **Tagger** (LEARNING, `LanguagePack.tagger`, `core/tagging/`): `tag(sentence tokens)` gives each token a tag, its dictionary part of speech (`label`), whether it is an inflected form, whether it is a proper noun, and a confidence; `threshold` says from which confidence a tag is trusted; `uses(tagged words)` is the language's grammar of how each word is used. English: an averaged perceptron (Penn Treebank tags) trained on UD English-EWT by the data build (`en/tagger.json`, `scripts/data/tagger.ts`; small weights pruned), with no dependencies. Its word-shape feature reads letters of any script (CORE, 2026-11-18: an upper- or title-case letter is X, any other letter x, so "Ángel" is "Xxx" like "Angel"; before, only ASCII letters were letters). The shipped `en/tagger.json` was trained with the ASCII shapes and is kept: only 8 EWT tokens hold a non-ASCII letter, so it scores the same under the new shapes (dev 92.50%, test 92.54%), while retraining gives dev 92.50%, test 92.40% and changes 1,434 hovers of the 2026-11 corpus by training-order noise (five shuffled orders spread 92.46–92.86% with either shapes; judged blind: changed hovers preferred 82 retrained vs 89 kept, units 30 vs 29). The next English data rebuild retrains it. Contractions are split for the tagger only ("do" "n't"); ALL-CAPS documents (casing mode "upper") are tagged in lower case. Its grammar: auxiliaries (have + past participle or "to", be + participle, do + bare verb, get + past participle, with up to three adverbs or an inverted subject between: "has spent", "does Harvey know", "had to", "got hurt"); how an inflected verb is used (finite, after an auxiliary, before a noun "demanding work", a state "was established" without "by"); a gerund after a determiner or adjective is a noun; where a participle can stand for a preposition (clause start, after a pause or a noun)
- **Spanish tagger** (LEARNING, 2026-11-18, step U2-2 of [spanish-quality](../notes/spanish-quality.md)): the same perceptron trained on UD Spanish AnCora (CC BY 4.0) and GSD (CC BY-SA 4.0) at pinned commits (`es/tagger.json`, `scripts/data/es-tagger.ts`, part of `npm run data:es`), over universal tags with the verb form of verbs and auxiliaries (VERB.Fin, AUX.Part, …: 23 tags), on the tokens as written: a contraction ("del", "dímelo") is one token with its first word's tag. - **Split** (CORE `core/lexicon/compounds.ts` `splitCompound`; LEARNING `COMPOUND_RULES`, German only): a word the language does not know (no base, not in the names lexicon) is read as its longest known head, a noun or an adjective, after a modifier: a word, a verb's stem (`stems`: "Schreib-tisch"), a noun with a linking element (`links` -es-, -en-, -er-, -s-, -n-, -e-) or without its final e (`dropped`: "Schul-buch"), or a compound itself, two levels deep ("Weltklima-konferenz"); parts of three letters at least (`minPart`). In a capitalised word the head is the first of its bases that is mainly a noun ("Lösungsangeboten": Angebot) and so is a modifier spelt like a verb ("Schienen-": Schiene), unless the modifier is an adjective, adverb, numeral or preposition as written ("Großprojekt"); a word that is also a verb heads one only by a form at least as long as it ("les" is lesen's stem). A verb modifies by its stem, its infinitive without the ending, not by another of its forms ("Sprach-": Sprache, not sprach, sprechen's past); a stem that is also a noun's base without its final e reads as the more frequent of the two (`CompoundWords.rank`: "Schul-", "Erd-", "Stimm-": Schule, Erde, Stimme; "Mess-": messen; C3, 2026-11-20: 16 German notes change, 15 judged better, "Spritzbeutel" worse). No pronoun, determiner or other function word is a modifier
- **The pack** (`LanguagePack.compound`, `lemmas`, `rank`, `partsOfSpeech`): the word's key is its modifier as written and its head's base ("Verdauungsenzyme" → `verdauungsenzym`), it ranks as its rarest part as a hyphenated compound does, and has its head's parts of speech. The classifier leaves unknown a lower-case word with a noun head in a punctuated mixed-case document of a language that capitalises nouns ("summende" is a participle, not summen + Ende); speech recognition without punctuation writes many nouns in lower case, so there it is read
- **The card** (`withCompounds`, every dictionary of a language with compounds, `language-resources.ts`): the headword is the key written as the head's entry writes its own (Bahnsystem), the note its parts' headwords ("Bahnsystem → Bahn + System", where a contraction's note stands), the first line its parts' first meanings joined ("railway + system"; brackets, an English article and what follows a slash or "or" left out: "key + noise", not "a key + noise"; the head's lines when wider than a line's cap), then the head's second line; the window shows the head's senses, and rule A1 reads the head's outline. Judged blind on 150 compounds (L2-2): joined meanings good 50–62%, the head's alone 0% good (84–98% acceptable), preferred 58 : 26
- **A part's sense** (CORE data `scripts/data/compound-senses.ts`, R3): Wiktionary's etymologies of compounds gloss each part with the sense the compound uses ("Eisen (“iron”) + Bahn (“railway”)"). Of a word's senses of its first sense's headword (a capitalised noun's are not a lowercase adjective's: Licht "light", not licht "bright"), the one whose first item shares a content word with the most of those glosses, three at least and more than the first sense, is its sense as a part, kept under its key and "-" in the dictionary pack (`bahn-`: railway; `fall-`: case; `klasse-`: class; 195 words), which the joined line reads
- **Feminines** (LEARNING `CompoundRules.feminine`, R3): a capitalised word the language does not know that is a known noun with -in or -innen is that noun's feminine before any split, keyed with -in ("Kommissarin": Kommissar, not Kommi + Sarin), and a head may be one ("Polizeikommissarinnen" → Polizei + Kommissar)
- **Names** (data, `LearningBuild.compounds`): the build adds to the names lexicon every proper name of the extract that the split would read as a compound (Deutschland, Frankreich, Lehmann; German 1,908 → 3,724 names), so that it stays unknown
- Over the German corpus 1,375 tokens gain a meaning (unknown 9.1 → 7.1%); New per 1,000 tokens 104 → 116 (compounds with a part beyond the known level)

### Names and written case
How a word is written on the page decides which meaning it shows, and whether it is a word at all. The rules are layered like the short lines:
- **Document casing** (`core/text/casing.ts`, language-independent): the content script reads a whole document before it is classified: a video's caption track (`content/video/session.ts`), an article's main content (`content/article/article.ts`, Title Case menus and links outside it say nothing; YouTube comments: every comment). Its mode is "upper" when over 60% of the words are ALL CAPS, "lower" when under 0.3% of the words inside sentences are capitalised (speech recognition), else "mixed". In mixed mode it counts, per word, the capitalised occurrences inside sentences and the lower-case ones. A word does not count at a sentence start (the sentence segmenter), after a colon, an opening quote, a closing bracket or a dialogue dash ("- Aww"), anywhere in a block in Title Case without a final period (a heading), inside brackets ([sighs], (Laughter)); ALL-CAPS words and plural acronyms (AEDs) count for nothing. `analyze` and `recordHistory` carry this casing (only words capitalised inside a sentence at least once); an article updates it as blocks come and go and classifies again the analyzed blocks with a word whose verdict changed. Nothing runs per hover
- **Accents in capitals** (CORE mechanism, LEARNING `CAPITAL_ACCENTS` in `language-pack.ts`; Spanish, 2026-11-19): text in capitals often leaves accents out (ESTAN, POLICIA, SEGUN). In an upper-case document, a word with no base forms is read as the one spelling with one of the language's accented letters (Spanish á é í ó ú ü ñ; French à â é è ê ë î ï ô ù û ü ç ÿ; any number a word, at most 4,096 spellings tried: ETE → été, DEJA → déjà) that the lemma table knows, unless that spelling is a name (BERLIN stays unknown, not berlín "donut") or two spellings are known; the matcher and the tagger read it so (`LanguagePack.accented`, `PhraseMatcher.prepare(tokens, upper)`). A word with a meaning as written is left alone (ESTA, not está). Over the Spanish corpus 72 tokens get a meaning (estar, policía, según, país, dólar)
- **Written case** (`capitalHere`): in a mixed document a word is capitalised in a way that counts inside a sentence, at a sentence start when the document writes it capitalised at least five times as often as in lower case, and as an acronym when ALL CAPS among words that are not (US, not "GIVE US MORE"), unless English writes the word in capitals as a common word (the names lexicon's "!": "OK", an interjection; U1-8: en-ja's OK showed Oklahoma first, the acronym's capital entry), whose capitals then say nothing. The span gets `capital`, and `run` when a capitalised word inside a sentence stands next to another capitalised word with only spaces between (a name's or a title's word: Oak Ridge National Lab, "American Buffalo"; 2026-11-20); the lookup sends `written` ("capital", "run", "upper", or "lower" for a word in lower case in a mixed document; nothing for a caseless document or a capital at a sentence start, and the word list sends nothing). An acronym with a possessive or plural ending is "upper" (DEA's, GPUs; not Ms), and so are capitals with periods between them wherever they stand (a start, brackets, among other capitals: "(DSS), U.S. State Department" showed ubi supra first)
- **Rule D, names** (`core/names.ts`): in a mixed document a vocabulary word is a name when the document capitalises it inside a sentence and never writes it in lower case, and the names lexicon has it: as a given name, or as a surname, place or organisation that is rare as a common word (beyond rank 3,000: Trump, Thatcher; not World, Park, Center), and not as a capitalised common word (English, Christian). Never names: a word whose main part of speech is a function word or an interjection (The, Yes, Oh), a word right after a determiner ("the Enlightenment"). A caseless document has no names. A name whose dictionary has a capitalised meaning of its own stays a word, capitalised: a gloss that says what it is (June → 6月, Japan → 日本), or the name in the native script for a word that is not a person's name first (Germany → ドイツ). Every other name is `ignored` (`Span.name`): no highlight, no hover, and the sentence history does not index it. Languages without case turn this off (`LanguagePack.namesByCase`: English, Spanish, from L1-3 French, from L2-2 German); so does a pack without a names lexicon. Where every noun is capitalised (`LanguagePack.nounsCapitalised`, German, L2-2), a capital says nothing by itself: a word is a name by itself only as a given name, as written (Dietrich, Jasmin; not Wolken, a plural the lexicon lists too), never in lower case, and not after its noun phrase's opener, which comes before the adjectives (a determiner or its inflected form, a numeral, a preposition joined to the article: "Der blaue Engel", "im Ernst"); a word after a person's name is theirs when the lexicon has it as a person's name or it is no noun (Albert Einstein, Jürgen Klopp, Robert Kohl), document-wide only when rare as a common word, else only there ("Franz Josef Kaiser", not "Kaiser Franz Joseph"); places and surnames by themselves stay words (Klima, Gouda). Over the German corpus 96 tokens become names, all of which had a word's meaning
- **Names lexicon** (LEARNING, `en/names.json`): Wiktionary's proper-name entries by lowercase word → their kinds (given name, surname, place, organisation, other), the main one first, and "!" for a word that also has a capitalised adjective, adverb, verb or interjection entry (English, Monday, God). Only vocabulary words and given names (15,709; 57 KB gzipped). Spanish (`es/names.json`, U2-4, 2026-11-19): kaikki Spanish's proper names that are vocabulary words, inflected forms of them (Argentina, Marina) or given names (2,466; 11 KB gzipped), and "c" after the kinds for a name that the usage examples of kaikki Spanish and of Wikcionario's Spanish entries write capitalised inside a sentence at least 3 times and at least twice as often as in lower case (487: Chile, Japón, Brasil, Luis): rule D counts it as rare whatever its rank, since the frequency list folds case ("chile" ranks 665 by the country). French (`fr/names.json`, L1-1, on from L1-3): the same from kaikki French, with the examples of kaikki and Wiktionnaire (2,031 names, 1,068 "c": Molière, Paris, Japon); over the French corpus (82,415 tokens) rule D takes 316 tokens for names (Tapie 34, Fabienne 24, Pierre 19, Paris 18, Piaf 17), all of which had a meaning before
- **Capitals only for names** (LEARNING, `LanguagePack.capitalsForNames`, Spanish and French; not English, which capitalises Germans, Democrats, March and US; French capitalises a people's noun, "les Français", a vocabulary word after an article, which the rule leaves to its tag): a capitalised word that is no name gets no `capital`, so rules A1 and A2 read it by its tag like any word ("Nueva York": nuevo; "Segunda Guerra Mundial": segundo; the es-en dictionary has no capitalised headwords apart). And a word the names lexicon lacks that is only an inflected form of a vocabulary word is a name, like a lexicon place, when the document always capitalises it inside sentences and its reading as the form is unlikely: every base is rare (beyond rank 3,000) and no noun (Bruna, not bruno's feminine; Afores, not aforar; a noun's plural in a title stays the noun: "Parque de Atracciones"), or it comes right after a capitalised word the language does not know at all ("Stephen Hales", not halar; "My Salad", not salar; "Rockstar Games"). Not a form of a function word, not after a determiner, and not in a document without punctuation, whose speech recognition capitalises turn starts ("Imagínate", "Mola"); the head-of-a-title rule below keeps it a word after a vocabulary word that is no name. Over the Spanish corpus (72,828 tokens) rule D takes 415 tokens for names (Marina 41, Chile 36, Mercedes 30, Sosa 23, Arcadio 20, Japón 18, Bruna 10, Salad, Hales), all of which had a meaning before, and changes no other hover
- **Capitalised headwords** (PAIR, `en-ja/capital.json`): EJDict merges case variants into one key with the lowercase senses first (japan → 黒い漆, 『日本』 last). The build keeps the senses of capitalised headwords apart: under the lowercase key for a capitalised word (japan → 『日本』, may → 『5月』), under the key in capitals for an acronym (US → 合衆国). A key with a lowercase headword keeps only its lowercase senses in the dictionary; a key written only with capitals keeps them there too and is listed under its lowercase key (Paris, David). A sense that only says the word abbreviates a capitalised English name ("Oklahoma(オクラホマ州)の略" of OK, "Coca Colaの略称" of coke) is a capitalised sense: it goes to `capital.json`, under the acronym when the line writes the word in capitals (OK), else under the capitalised key (Coke), unless it is the headword's only sense (U1-7, 2026-11-19: okay's "=OK,O.K." showed Oklahoma first) Capitalised or in capitals: those senses alone when they mean something (`capitalMeaning`: not about one person, a people or a symbol — EJDict writes those with a lifespan, 聖, …人, 記号, or a work's title in brackets — and with a Japanese gloss, or an acronym's expansion), the card headed as the headword is written (U.S., US, Japan; 2026-11-20: U.S. was headed "u.s." and listed ubi supra's 上述の箇所に, Japan lacquer, US the pronoun, Turkey the bird); in a run of capitals ("run"), those senses first, then the lowercase ones, as the capital may be the name's (Oak Ridge National Lab: 労働党, then 実験室); lower case: the lowercase senses alone; not said: lowercase, then capitalised. The dictionary window follows the same lookup; word lists show every sense, as before
- **Abbreviations spelled out** (CORE `core/lexicon/expansions.ts`, 2026-11-20; [notes](../notes/proper-nouns.md)): an initialism stands for several things in the dictionary's order (DEA: diethanolamine first, the Drug Enforcement Administration second), and a text that means one tends to write it out where it first uses the abbreviation. A word the page writes in capitals (`written` "upper") sends its document's text with its lookup (the article's main content, the video's caption track); the card leads with the first sense whose expansion the document writes, as whole words in any case: a sense's leading Latin words whose initials are the abbreviation's letters, short lowercase words aside ("Initialism of Drug Enforcement Administration." → Drug Enforcement Administration; EJDict's "Prime Minister", "District of Attorney (米国の)地方検事"; a recipe pair's English hint; en-defs' "graphics processing unit: A specialized…" and en-ja's "《central processing unit》中央処理装置", which the data build heads with what the abbreviation stands for, "Their meanings" in rule E), two words at least, each of a sense's alternatives joined by "or" (2026-11-20: ANC's "active noise control or active noise cancellation", which an earbuds review spells out). `senses` stay in the dictionary's order. Not for an abbreviation in lower case: "p.m." in a text about the Prime Minister is still 午後. The document's other words (a sense's words it also writes, rarer than rank 300 or 1,000, with margins) chose wrongly as often as rightly (CV a résumé → computer vision in an article about video interviews, FC → foster care, M.O. → Medical Officer, RPG → rocket-propelled grenade in a game video), so they are not read
- **Capitalised headwords of the recipe pairs** (U1-3, 2026-11-19; PAIR data build `capitalDictionary`, NATIVE `nativeKindOf`, CORE lookup in `createPairDictionary`): every recipe pair keeps the capitalised single-word headwords of its edition (proper nouns too) and of the translation tables apart, merged from the same sources in the same order as its terms, in `capital.json` under `capitalKey`, acronyms (two capitals or more, no lower case) apart from the rest as en-ja keeps them (Japan → Japón, January → enero, Thursday → jueves, I'm, British → británico; US → EE. A word with no lowercase entry takes its capitalised one however it is written, so no lowercase copies are stored. What a headword means is decided at build time and stored with it (`capitalMeaning`):

  - a table sense whose English sense is about a person's name (the names lexicon's given-name and surname patterns: "transliterations of the surname") is left out while the headword has another meaning: no person's name is a line of a language's or a nationality's word (ru English: Инглиш; U1-6), and a table sense outside standard use too (it English: "silvio", a dated size of type);
  - the sources keep every sense of a capitalised headword; an edition's come in turns by part of speech (the first of each, then the rest: fr English → anglais, "anglais, langue anglaise", then the adjective's others), as a capitalised word's hover is not ordered by its tag, and all are capped at four after the above (U1-6); an exclamation's turn comes last (U1-9: pt God → Deus, then "interjeição que mostra frustração"; a capitalised word said as one is the word used so);
  - an edition's gloss opens with the case the translation tables write that word in for the same headword (U1-9, `inTablesCase`): es March "Marzo" → marzo, Sunday "Domingo" → domingo, fr March "Mars" (the planet's spelling) → mars, January "Janvier" → janvier, pt January "Janeiro" → janeiro; a word the tables also write capitalised stays (Dios, China, German Januar);
  - a first gloss that is the headword itself, accents and case aside, is no meaning (Texas → Texas, German Japan → Japan, Paris → París): the word stays a name;
  - "word" or "name" by the native edition's own entry for the gloss: lower case is a word; a capitalised gloss the edition has in lower case as a common word is that word (Wikcionario and Wiktionnaire capitalise every gloss: "Enero", "Mayo", "Janvier"); else one it files only as a proper noun is the name (Japón, Frankreich, 日本); else a common noun is a word where the edition capitalises most of its nouns (German: Januar) and the name where it does not (Russian files Япония, Эйнштейн as nouns); else by shape (capitalised words: the name, others a word; in a caseless script none: zh "Oh" → 源自朝鲜语的姓氏, a surname from Korean, is no name), else, in a caseless script, a sense of a common word's part of speech is a word (zh English: 英国人的; a proper noun's says nothing; U1-6);
  - a "word" meaning of a person's name first (the names lexicon's main kind a given name or a surname) is a use of the name, not its meaning (Einstein → gênio, Frank → franco): none. ## Choosing a translation
Use the site's translation when it has one; fall back to the browser's built-in translator only when it doesn't. Site translations are often human-made and need no on-device processing.

| Order | Source | YouTube | Netflix | Articles |
|---|---|---|---|---|
| 1 | The site's **native-language subtitle track** (human-made) | manually added Japanese subtitles | Japanese subtitles | — |
| 2 | The site's **machine translation** | auto-translation of the original subtitles (fetched with `tlang=ja`) | — | — |
| 3 | **The browser's built-in translator** | Translator API | Translator API | Translator API |
| — | none | no translation | no translation | no translation |

- Pick one per video and never switch midway; a change of the language pair while the video is open loads its subtitles again and picks anew. When a video uses the site's translation, lines without a translation are not filled in by the built-in translator (meanings would overlap and the phrasing would clash)
- **Timing**: a site's native-language track has different line breaks and timestamps from the original (especially Japanese subtitles on Netflix)
  - Subtitle translation: look up the translation track separately by playback position and show the translation on screen at that moment as is
  - Transcript cards (rule G, many to many): each translated cue goes to the card (sentence) it overlaps most in time (ties to the earlier card), and also to every other card of its kind (spoken or sound label) that it covers at least half of, so a condensed line spanning two sentences shows on both. A card joins all its cues in time order. A spoken line goes to a sound-label card only when it overlaps no other card. The half was measured on human Japanese tracks timed apart from the English (and on the same tracks condensed): it leaves almost no card without a line while lines with a neighbour's text barely grow; a lower share mostly adds grazing neighbours, and asking the cue to lie mostly in the card too gives back most of the empty cards. Before rule G, adjacent sentence cards that one translated line covers at least half of each are joined into one card while it stays within 30 words (`joinCoveredCards`, 2026-11-15): a translator often puts two short sentences into one line, which would otherwise show on both (the same line on two cards in a row: Netflix 4.3 → 0.1%, YouTube 2.9 → 1.3%). YouTube's machine translation keeps its own rule (cards follow its sentences, see "Transcript")
  - YouTube's auto-translation comes back with the same breaks as the original, but YouTube translates sentence by sentence and spreads each sentence over the cues it covers, so for manual and auto-generated tracks alike the cards come from its sentences (see "Transcript"); a manual track's cards stay whole cues
- The occurrence's `translation` stores the translation shown at that time
- Articles have no site translation, so only the built-in translator is used
- The built-in translator's model is downloaded once per pair and needs a user activation: it starts at the first click, tap or key on a page Langle runs on, when the toolbar popup opens, or when a language is chosen in Settings, whichever comes first ("Definitions translated at display time")

## Data model (IndexedDB)
- Dexie schema versions 4 to 6. Versions 1–3 only added tables and were merged into 4 (2026-11-12); Dexie upgrades an older database by comparing the schemas. Version 5 adds your meanings, version 6 the on-device AI's answers (`explanations`; phase 3)
- `terms`: `{id: "en:look up", lang, key (base form or sequence of base forms), display, kind: word|phrase, status: learning|known, bulk?: bool, learnedAt?, note?, createdAt, updatedAt}`
  - Words saved by "save all" (Mark as Known at the end) get `bulk: true` (for demotion when sync space runs out)
  - `learnedAt`: when a live term last went from `learning` to `known` (the word list's Learned, [ui](ui.md) "Word list page"). Set by that change only; going back to `learning`, removal and a sync record without the mark drop it; saving a known term again keeps it
- `sources`: `{id, platform: youtube|netflix|web, url (normalized), title, lang, firstSeen, lastSeen}`
- `occurrences`: `{termId, sourceId, sentence, translation?, pos: {timeMs}|{textQuote}, seenAt, origin: saved|encountered}`
  - Saving always creates one source record
- Sentence history (never in browser sync or the JSON export; synced only to the user's own cloud, see "Sync to the user's own cloud storage")
  - `historyPages`: `{id (= source id), platform, url (normalized), host, title, lang, firstSeen, lastSeen, bytes}`
  - `historySentences`: `{pageId, text, translation?, pos, keys: termId[], seenAt}`, unique per page and text, indexed by `keys` (every base form of each word outside the 300 most common, plus the phrases found in the sentence)
  - Articles keep the sentences of the blocks Langle analyzes as they come near the view (blocks "Words on this page" analyzed earlier are kept, and their saved words recorded as encounters, only once they come near: 2026-11-14); videos keep **played lines only**. Not kept while the switch is off, while Langle is switched off in the popup header, or on hosts in "Never run on" / switched off in the popup; adding a host to "Never run on" removes its pages. Size is counted by Langle (UTF-16 size of the strings plus a fixed overhead); over 50 MB, the oldest pages (`lastSeen`) are removed until under 45 MB
  - Saving a word (not "save all") copies its kept sentences into its occurrences (`origin: encountered`, up to 50)
  - Meeting a saved word again records it automatically (deduplicated by source + sentence, at most 50 per word; the oldest encounters go first, the sentences the word was saved from always stay)
  - YouTube links use `&t=` to jump to the spot
  - Only pages/videos opened with the extension on are recorded
- Phase 3: `meanings` and `meaningChoices` ("Meaning in context" → "Your meanings: data"); `explanations` ("Meaning in context" → "Answer"; device only, never synced or exported)
- Settings live in storage.sync: language pair, interface language, frequency level, highlight categories, external dictionaries on/off, subtitle position, translation visibility (subtitle / transcript), subtitle text size and background, what to do with unsaved New words at the end, per-site on/off and the exclusion list, and the L button's on/off per video platform

## Sync (browser `storage.sync`; limits: ~100 KB total, 512 items, ~8 KB per item)
- `BrowserSyncBackend` (background) owns it. `CloudSyncBackend` (designed, not built: "Sync to the user's own cloud storage") takes over terms while connected; no shared interface is kept until it is built
- The limits are the same in Chrome and Firefox. Use the `storage.sync` constants (`QUOTA_BYTES` etc.) when readable at runtime, otherwise the values above
- Per language, sort `term key → status code + updated time (minutes in base36)`, concatenate, gzip (CompressionStream) + base64, and store in chunks of ~7 KB
  - Status codes: `l` learning, `k` known, `g` known and learned (`learnedAt` set), `x` removed. A device that takes in `g` keeps its own `learnedAt` when its copy is already learned, else uses the record's update time
- **Rough capacity**
  - Uncompressed: **~6,000 words**
  - Compressed: **~12,400 words** (English, measured 2026-11-09 with realistic save times; 20,000 words take ~170 KB)
  - Words within the frequency level do not count
  - When the limit gets close, demote words saved by "save all" to "this device only"
  - Over 90% of the room left by other keys (settings, other languages): leave out "save all" words oldest first; if that is not enough, leave out the oldest known words too and report how many. They stay on the device
- Merge: per word, the newer update time wins (same minute: keep this device's); deletions are tombstones, carried for 90 days. Pick up other devices' changes with `storage.onChanged`
- Each push reads and merges the synced copy before writing it (chunks first, then `sync:<lang>:meta` = `{chunks, updatedAt, v}`, then stale chunks are removed), 2 s after the last local change. Pulled changes are not pushed back unless this device has newer ones. Storage errors (quota, write rate) show in the status and are retried with backoff
- Sources and occurrences stay on the device. JSON export/import moves all data

### When the browser is not signed in / sync is off
- `storage.sync` does not fail; it just stores locally (behaves like `storage.local`). The quota still applies, so demotion near the limit works the same
- If the user signs in and turns on sync later, data merges with other devices by per-word update time. Nothing special is needed
- The extension has no reliable way to know whether data reaches other devices (`set()` succeeds once written locally)
  - So the UI never claims "synced"; it shows **only the last saved time and usage**
  - Do not request the permission for checking sign-in (`identity.email`). It adds an install warning and still cannot tell whether sync is on
- Users without sync lose everything when they change devices or remove the extension (removing it also deletes IndexedDB). JSON export is the safeguard, so Settings "Backup file" shows the last export time

### Sync differences by browser
| | Chrome | Firefox |
|---|---|---|
| Sync target | Google account | Mozilla account (stored encrypted) |
| User requirement | signed in with sync on | signed in, with "Add-ons" on in sync options |
| Delay | almost immediate | about every 10 minutes, or "Sync now" |
| Other | — | `browser_specific_settings.gecko.id` is required in the manifest (without it `storage.sync` does not work). Not synced on Android |

- The sync name ("Chrome sync", "Firefox Sync") comes from `BrowserEnv`. Saving and merging do not differ by browser

## Sync to the user's own cloud storage (designed 2026-11-15, not built)
Google Drive, Dropbox and OneDrive, with no developer server. Built later; the steps before building are under "Checks before building". The mobile app ([notes](../notes/mobile.md)) cannot read browser sync, so this is also how it gets data and settings: the file format is a contract, and the mobile app reads and writes the same files. Reviewed by an independent agent on 2026-11-15; its findings are folded in.

### What is synced
| Data | File |
|---|---|
| Terms (words and phrases): key, display, kind, status, `bulk`, note, created / updated / cleared / learned times. Tombstones are kept for good | `main` |
| Sources that still have an occurrence | `main` |
| Settings (everything in `storage.sync` today) with a time per field | `main` |
| `historyClearedAt` (the last "Clear") and `historyForgotten` (host → when it was added to "Never run on") | `main` |
| Occurrences, saved and encountered ("Seen elsewhere"), with the sources they use | `occurrences-YYYY-MM` |
| Your meanings (phase 3, "Meaning in context"): the meaning choices this device made, undone ones included, and the meanings they name | `main` |
| Sentence history (pages and sentences), unless "Also save to <provider>" is off; the newest 50 MB over all devices | `history-YYYY-MM` |

- Not synced: sign-in tokens, the device id, `lastSavedAt` / `lastExportAt` / `historyBytes`, downloaded packs, the translation cache

### Browser sync while connected
- A connected device stops reading and writing **terms** in `storage.sync` (no quota and no demotion), and the browser-sync switch for terms is hidden. Settings stay in `storage.sync` as well, so desktops still get them at once
- Connecting first pulls `storage.sync` into IndexedDB, then writes the cloud files. Every term in browser sync moves to the cloud; local tombstones (kept for good while connected) beat stale copies there
- Terms left in `storage.sync` are not removed: devices not connected yet keep using them, and merge when they connect
- The chosen provider is a synced setting (`cloudProvider`). A device that gets it but is not connected shows "Connect <provider> on this device too" in Settings and the popup (sign-in is per device)
- Disconnecting resumes browser sync for terms; the usual merge brings it up to date
- **Switching provider**: the device that switches writes its whole copy to the new provider. Devices still connected to the old one show "Reconnect to <new provider>" and keep syncing with the old one until they do. Files at the old provider are left as they are

### Data model changes (the next Dexie version after 6)
- `occurrences` and `historySentences` gain `deviceId` (the device that first recorded the row) and `addedAt` (when it did). Rows taken in from other devices keep theirs. Existing rows get this device and the upgrade time
- `terms` gain `clearedAt`: the last time the term was removed. Saving it again keeps it, so the occurrences it had before the removal never come back
- Local tombstones are no longer pruned while connected (the 90-day limit stays for `storage.sync` only)

### Files
- In the provider's app-only space (Drive `appDataFolder`, Dropbox app folder, OneDrive `approot`): `devices/<deviceId>/main.json.gz`, `devices/<deviceId>/occurrences-YYYY-MM.json.gz`, `devices/<deviceId>/history-YYYY-MM.json.gz`
- `deviceId`: random, made at install, kept in `storage.local`. If this device's `main` turns out to have been written by someone else since its last write (a copied browser profile), it makes a new id and starts a new folder
- Every file is gzipped JSON `{format: "langle-cloud", v: 1, kind: "main"|"occurrences"|"history", deviceId, writtenAt, …}`
  - `main`: terms (tombstones included), sources still in use, settings with field times, `historyClearedAt`, `historyForgotten`
  - A month file: the rows **this device recorded** (`deviceId` = its own) whose `addedAt` falls in that month, plus the header of every source or page they refer to, with the times this device has for it. A page or source seen again without new rows still goes into the current month's file, so its later `lastSeen` spreads
- **A device writes only its own files.** No two devices write the same file, so no locking or conditional writes are needed with any provider. Other devices' files are never removed automatically
- Writing: `main` only after a **local** change (not after taking in other devices' changes, which would make every device rewrite on every change). Month files: every month that has rows not sent yet, past months included (a row imported with an old time, a write left over at the turn of a month). Unsent months are remembered in `storage.local`
- History limit in the cloud: after merging, every device knows the same oldest page it keeps under 50 MB; each device removes **its own** history month files that hold only older pages. Occurrence month files stay (occurrences are already capped at 50 per term)
- Size (estimate, measure when building): 10,000 terms → `main` well under 1 MB gzipped; occurrences of a heavy user up to ~200 MB raw over all months, which is why they live in month files

### Merge (shared with JSON import, which moves to the same rules)
- **Order of reading**: every `main` first, then month files. A month file counts as read only when each row was taken in or dropped for good; rows for a term not known yet leave it to be read again next time
- **Terms**: the newer `updatedAt` wins; tombstones count like any version; `clearedAt` takes the later of the two
- **Occurrences**: taken in only if the term is live and `addedAt` ≥ its `clearedAt`. Rows are matched by (term, source, sentence); when two copies differ, one fixed order decides: `saved` beats `encountered`, then the earlier `seenAt`, then the earlier `addedAt`, then `deviceId`. The trim (50 per term, oldest encounters first; saved sentences and, in phase 3, sentences with a meaning chosen stay) breaks ties the same way, not by the local auto-increment id
- **Meaning choices** (phase 3): by (term, source, sentence), the later `at` wins (an undo is a choice of none); taken in only if the term is live and `at` ≥ its `clearedAt`. Meanings: the union by `key` (the same key is the same meaning)
- **Sources and history pages**: ids come from the URL; first/last seen times only widen; equal `lastSeen` → the lexically smaller title
- **History sentences**: matched by (page, text), the same fixed order for differing copies; dropped if `addedAt` < `historyClearedAt` or the page's host is in `historyForgotten` with a later time. Then the 50 MB limit (oldest pages go until under 45 MB). "Seen elsewhere" lists order by `seenAt`, not the auto-increment id
- **Settings**: per field, the newer field time wins; defaults count as time 0, so a fresh install or the mobile app changing one field does not overwrite the rest. A settings item written by an older Langle (no field times) counts its differing fields as changed when it arrives. Taking in `historyForgotten` from the cloud runs the same removal as adding a host locally
- The result does not depend on which device reads which file first. Known limit: a device whose clock runs ahead wins every "newer" comparison, as with browser sync today

### Parts
- `CloudSyncBackend` (background): reads, merges and writes the files; knows no provider
- `CloudProvider`, in two halves
  - **Files**: `list()`, `read(path)`, `write(path, bytes)`, `remove(path)` over `fetch`, shared by the extension and the mobile app
  - **Auth**: only returns an access token. Desktop: `identity.launchWebAuthFlow`; for Google, `identity.getAuthToken` where it exists (Chromium; detected, not by browser name: Chrome renews the token itself, but only for the Google account signed in to the browser). - Permissions: `identity` shows no install warning in Chrome; whether Firefox accepts it as an optional permission, and whether the providers' APIs need host permissions at all (all three allow cross-origin requests), are checks before building
- One app registration per provider, reused by the mobile app (adding its redirect URIs / client types): the app-only space belongs to the registration (Drive: to the Cloud project, which also holds the Chrome-extension client for `getAuthToken`)

### Timing
- Write 30 s after the last local change. Pending writes are remembered in `storage.local` and done at the next start
- Read: at start, every 5 minutes (`alarms`), and when the popup or Word list opens. List first, then download only files whose modified time changed

### Status and errors

- Network errors and 429: retry with backoff (up to 10 minutes)
- 401: renew without a window; if that fails, "Reconnect needed". Changes keep collecting in IndexedDB
- Storage full: shown in the status, writing stops, nothing is lost on the device
- Another device's file unreadable or of a newer `v`: skip that file and show "Update Langle on this device"

## Meaning in context (phase 3; designed 2026-11-15, built 2026-11-16)
What the user sees: [ui](ui.md) "Meaning in context and your meanings" (mock approved 2026-11-15). Decisions: [design](design.md) "Phases". The steps before building are under "Checks before building" below. Built: your meanings (M1a, M1b), the core with a fake provider (M2, 2026-11-16: `core/explain/`, `content/explain/`, the `explanations` cache), the Chrome provider and the UI (M3, 2026-11-16), checked with the real model in the user's Chrome (M4, 2026-11-16: [notes](../notes/meaning-in-context.md) "Real-site check (M4)"). Nothing runs without a provider.

### Parts
- `ExplanationProvider` (`core/explain/provider.ts`): one language model behind one small interface, so the mobile app and an API key later add an implementation and change nothing else
  - `name` and `version`: part of the cache key (`chrome-prompt-api` and the browser engine's major version, its "Chromium" brand in `navigator.userAgentData.brands`, never the user-agent string: the API names no model version)
  - `availability({learning, native})`: `ready` | `downloadable` | `downloading` | `unavailable`, for that pair (Gemini Nano does not read and write every language; an unsupported one is `unavailable`). This, not whether `LanguageModel` exists (it exists even on devices that cannot run it), decides whether the UI shows anything. Asked again whenever the dictionary window opens on a term, and when Settings opens or its pair changes: Chrome removes the model when free disk runs low. Chrome is asked with `expectedInputs` English (the instructions) and the learning language, `expectedOutputs` the native language; its values `available`, `downloadable`, `downloading`, `unavailable` and the older `readily`, `after-download`, `no` are read, anything else is `unavailable`
  - `download(pair, onProgress)`: only inside a user activation (a click): Chrome's `create()` called in the click, its `monitor`'s `downloadprogress` as a share (`loaded`, or bytes of `total` in older versions), the session destroyed. `downloading` is treated as `downloadable`: Chrome asks for a user activation for both, so pressing Download again joins the download running
  - `session(pair, instructions, signal, onStarting?)`: an `ExplanationSession` for one prompt with the instructions given first (a system prompt), so a provider can keep one base session per page and give a `clone()` of it. A retry gets a new session (it does not see the bad answer). `onStarting(true)` when the session waits for the model itself to start (Chrome: the base session's `create()` still pending, for this prompt or an aborted one before it), `onStarting(false)` once it has; never when the model is up already, nor after the signal aborts. The panel shows "Starting on-device AI…" when the start has lasted 1 s (`STARTING_NOTICE_MS`), and "Thinking…" again once it is over (ui "Meaning in context and your meanings")
  - The session: `budget` (the input tokens one prompt may use: `contextWindow`, older `inputQuota`, less what the instructions take, `contextUsage`), `measure(text)` (current Chrome: `measureContextUsage`, older `measureInputUsage`; Chrome 157 does not count the schema, so the answer's room includes it), `prompt(text, schema, signal)` (the answer as JSON text constrained to `schema`; aborted by `signal`), `destroy()` after the answer or an abort
  - Implementations: `ChromePromptApi` over `LanguageModel` (`content/explain/chrome-prompt-api.ts`; detected by whether it exists, never by browser name; one per content script, shared by a YouTube video and its comments, and one in the Settings page). Later: `NativeBridge` for the mobile app (Foundation Models on iOS 26+, the ML Kit GenAI Prompt API on Android; [notes](../notes/mobile.md) "Open issues" 9), then `UserApiKey` as a step of its own (consent, store review, privacy policy). Tests use the fake in `testing/explain.ts` (scripted answers, an answer that never comes, a token per four characters)
- `core/explain/` (browser-free, shared by every provider): `prompt.ts` (the instructions, the prompt, the lines' alternation), `context.ts` (how many lines fit), `answer.ts` (the schema and `checkAnswer`), `ask.ts` (one explanation: session, context, prompt, check, one retry). Its tests run with the fake provider
- `content/explain/`: `place.ts` (the sentence, the term's marks and the lines around it, from a video's cards or a page's blocks), `runner.ts` (the page's explanations one at a time, the cache, the time limit), `panel.ts` (the dictionary window's "In this sentence": what it shows as the window opens and its buttons are pressed, shared by the video and article parts), `chrome-prompt-api.ts`
- The window's section (`panel.ts`): each time the window opens on a term (not when it is looked up again after a change), the running prompt is aborted and the section hidden; then the pair's availability (`unavailable`: no section), then the cache (a kept answer shows at once, also while the model is not on the device), then `downloadable`/`downloading`: the download card; `ready`: the button, or the prompt at once for a term without dictionary meanings while `explainUnknown` is on. Try again reads the availability again. The answer's meaning is not listed again among the Meanings (`meaningRows` leaves out the AI meaning with its text), and the sense it names is marked "Fits here"
- Where it runs: like the translator, in the content script (check 1: `LanguageModel` is there in top frames, and in iframes whose embedder allows `language-model`; elsewhere `availability()` says `unavailable`), with the answers kept by the background (`explanations`). A click in Langle's shadow DOM is the user activation a download needs
- One prompt at a time per page (`createExplainRunner`, one per page). A new one (another term, the window closed: `cancel()`) aborts the one running, which rejects with an `AbortError` the UI ignores. It does not share the translation queue
- One base session per page holds the instructions; each prompt runs in a `clone()` of it (check 2: saves 0.65 s per prompt), destroyed after the answer. The base is not aborted with the prompt that asked for it (the next prompt uses it); a base for another pair replaces it, and one that fails to be made or cloned is made again next time. Budget: `contextWindow` (older `inputQuota`) less `contextUsage` (older `inputUsage`) of the clone; `measureContextUsage` (older `measureInputUsage`)

### Context (what one prompt holds)
- Fixed part: the instructions (English; answer in the native language), the learning and native languages, the source's title, the term as written and its base form, its kind, the sentence with the term marked (each part of a phrase with a gap), and the dictionary's meanings as the pack has them (an English definition in English, not its display-time translation), numbered, with their parts of speech. A term without an entry has no list, and its `sense` is always null
- Up to 5 lines around the sentence, alternately before and after (before first), each whole (check 3: the sentence alone, 5 and 20 lines fit equally often; more lines only add time). The lines are the learning language only: a site translation did not help (check 3) and machine translations would add noise
  - Video: the transcript cards around the term's card (cards are sentences), each as saving records it (its lines joined); empty cards and sound labels ("[Music]") are skipped. The sentence is the term's card
  - Article: the sentence as saving records it, then the other sentences of the same block, then the blocks before and after in document order. YouTube comments: the comment, then its thread (`PageSurface.contextRoot`: the blocks inside the comment's `ytd-comment-thread-renderer`). A part of a gap phrase in another sentence of the block is not marked
- Budget, as a guard (a line can be very long): one `measure()` of the whole prompt; while it is over the session's budget less 400 tokens (`ANSWER_ROOM`: the schema and the answer; check 1 measured about 370), the farthest line is dropped and the prompt measured again. When even the sentence alone is over, there is no prompt (an error: "Couldn't explain this."). The number of lines used is kept with the answer (the card no longer shows it, 2026-11-16)

### Answer
- JSON constrained by a schema: `{meaning: string, sense: integer | null}`, in that order. `meaning` is short (a hover line: about 25 Japanese characters or 40 Latin ones) and translates the marked words only, not the words around them ("not", "can't", the subject or object); `sense` the number of the fitting dictionary meaning, or null. No explanation (2026-11-16, [notes](../notes/meaning-in-context.md) "When to show an explanation": judges found 4% of terms need one; every gate tried, an `unusual` boolean or a `use` category, still showed explanations that were wrong 24–39% of the time; the meaning alone fits as often and answers 0.65 s faster). The scope sentence cut meanings wider than the term from 38% to 32%
- Instructions in English, the answer in the native language; two example answers in the native language: "bank" by a river (one of several dictionary meanings) and "spilled the beans" (an idiom without an entry) (check 4: Spanish answers fit 97%, English 90%, Japanese 88%; Portuguese is `unavailable` in Chrome 157). French and German have their own examples (the Prompt API answers in en, ja, es, de, fr); Russian has none and is `unavailable`, so meaning in context is offered without it, like Portuguese
- Checked (`checkAnswer`): a `sense` that is not one of the listed meanings (out of range, not an integer, any `sense` for a term without an entry) becomes null; fields outside the schema are dropped; `meaning` is trimmed and cut at 200 characters. An empty `meaning` or text that is not a JSON object is asked again once, in a new session, then is an error; an error the model throws is not asked again. Errors, and no answer within 30 s (counted from the cache miss, retry included), show "Couldn't explain this." with Try again. With the real model (M4) the slowest seen was the first prompt in a browser session, base session included: 10.2 s; no prompt failed or hung, and nothing reached the check build's error log
- Selected words (2026-11-19, ui "Correcting a selected phrase"; [notes](../notes/meaning-in-context.md) "Correcting a selected phrase"): the window's input has `selected`; for a learning language with a phrase note (`selectedNote` in `core/explain/prompt.ts`: English), the prompt ends with it and the schema is `PHRASE_ANSWER_SCHEMA`, `{meaning, sense, phrase}` (the phrase last: asked first, it was named less often and less accurately). The note is in the prompt, not the instructions, so the page's base session and every other term's answers stay as they were; `answerVersion` hashes the note and its schema too, so a selection's kept answer is its own. `checkAnswer` keeps `phrase` (trimmed, "" over 100 characters)
  - The panel sends the phrase to the background (`checkPhrase` with `proposal`), which puts it in dictionary form and checks it with the pack (`core/phrases/correct.ts`, `correctPhrase`): the words found in the sentence as the dictionary's pattern for them (`matchSelection` over them), else in dictionary form (a word tagged as a verb as its base that is a verb; a word that fills a slot, after the first word and tagged a pronoun or a determiner, as the slot: a possessive as `PhraseRules.ownSlot`, else `possessiveSlot`, another as the first other slot it fills), else the text as typed, else the text without its slot words when that is a pattern (`put something away` → `put away`). The first key that matches the sentence in saved mode (as it would be highlighted once saved) over a selected word wins. A proposal must also not repeat the selected words, correct them (other words, or a slot: `corrects`) and be one of the pack's patterns (`isDictionaryPhrase`); otherwise the card offers "Edit phrase" only. The edit sends what was typed without `proposal`: `words` (fewer than two) and `sentence` (not here) come back as the line under the field
  - Saving: the part (`saveCorrected` in `video/session.ts`, `article/article.ts`) saves the key as Learning with the sentence's occurrence (`saveTerm`, `display` the phrase's words in the sentence), classifies again, and opens the window on the phrase's new span in the same card or block. The selected words stay unsaved
- Cache `explanations` (IndexedDB, background; Dexie version 6: `explanations: "key, usedAt, pair"`): keyed by the learning and native languages, the term key, the source (its normalized URL), the sentence text, the provider and its version: the browser's major version (the API names no model version; a Chrome update may bring a new model) and `answerVersion`, a hash of the pair's instructions and the schema, so a changed prompt asks again; the row key is the JSON array of those fields. It holds the answer and its number of lines; 5,000 rows, least recently used out (`usedAt` set on every read); device only, never exported; cleared with the pair's packs in `removePack` next to the machine translations (their meanings may change)
- Messages: `getExplanation` (the key; the kept answer or null) and `putExplanation` (the key, the answer and its lines; a malformed key or answer is skipped: a pair Langle does not offer, an empty or over-long field, a URL that does not parse, more than 5 lines). The runner reads the cache first (best effort: an unreadable cache asks the model) and keeps a new answer without waiting

### Your meanings: data
Built 2026-11-16 (M1a: data, messages, export, the dictionary window; M1b: the hover card, the Words lists, the word list page). Two new tables (Dexie version 5: `meanings: "key, termId"`, `meaningChoices: "[termId+sourceId+sentence], termId, meaningKey"`). The choice made for a sentence is its own record, not a field of the occurrence, so another device's sentences, undoing and replacing all merge by time, and saving or importing an occurrence never touches it.
- `meanings`: `{key, termId, from: dictionary|ai, text, glossLang?, pos?, explanation?, createdAt}`. `key` is the SHA-256 of the JSON array [termId, `from`, text], base64url (`core/meanings.ts`; import refuses a file whose keys do not match), so the same meaning made on two devices, or imported, is one row. A dictionary meaning keeps the sense **as the pack has it** (an English definition stays English, with `glossLang`) and its part of speech; it is translated at display time like every other sense, and the window matches its Meanings rows by part of speech and pack text, so a translation that differs between devices or a pack update that reorders the senses does not lose it. An AI meaning keeps the model's answer (already in the native language); `explanation` only on meanings saved before 2026-11-16, when the card could show one
- `meaningChoices`: `{termId, sourceId, sentence, meaningKey | null, at, deviceId}`, one per (term, source, sentence), the same identity as an occurrence (occurrences are unique per source and sentence, so a line said twice in a video is one place, and every chip of it shows the meaning). `meaningKey` null is an undo. The latest `at` wins; at the same `at`, the smaller `deviceId`. `deviceId`: random, made on first use, kept in `storage.local` (`deviceId`), the id cloud sync will use
- Choosing a meaning for "this sentence" writes the `meanings` row (if new) and the choice. "This sentence" is the occurrence the window was opened from: the line, card or article sentence; from a Words row, the term's earliest place in the video or page. A saved term without that occurrence gets it now (`origin: encountered`); an unsaved term is saved as Learning with this sentence (`origin: saved`). Undoing writes a choice of none and leaves the term saved
- Read side: an occurrence's meaning is the live choice for its (term, source, sentence); "your meanings" of a term are the meanings its live choices name. A meaning no live choice names is dropped locally only (never as a tombstone, so a device that has not read every file yet cannot remove a meaning others use)
- Occurrences with a live choice stay when encounters are trimmed, like the sentences the term was saved from, so a term can keep more than 50 occurrences (only the ones the user chose meanings for)
- Removing a term deletes its choices and meanings on every path that deletes its occurrences today (`removeTerm`, a removal taken in by `importJson`, and by `applySynced`). A choice older than the term's `clearedAt` is not taken in again (the occurrences' rule). Until `clearedAt` exists (cloud sync), a choice is taken in only while its term is live: an import with an older choice for a term removed and saved again here brings it back, as occurrences do today
- Order wherever several show (hover card, lists): the meaning chosen for the hovered or listed sentence first, then most choices, then the most recently chosen (its latest choice's `at`). The dictionary window lists the meanings that are not one of the entry's senses first (the AI's, and a dictionary meaning a pack update took away, in its stored text), in that order, then the entry's senses in the pack's order
- Sync: not in `storage.sync`, which only has room for each term's status: on another device with browser sync only, the term arrives without its meanings (the UI says nothing about it and never says "Synced"). The JSON export carries both tables (format version 2; import reads versions 1 and 2, version 1 without meanings) and import merges by the same rules. Own cloud storage (designed above): each device's `main` holds the choices it made and the meanings they name; merged as in "Merge"
- Messages: `chooseMeaning` (the term as `saveTerm` sends it without a status, and the meaning or null); `lookup` takes `sentence` and returns `yourMeanings` (with counts, in the order above) and `chosenHere`; each `OccurrenceView` has its `meaningKey`
- Lines (M1b, `background/meaning-lines.ts`): every meaning the hover card and the lists show comes with its `line` (`MeaningLine`): a dictionary meaning as the line its sense makes (`DictionaryProvider.senseLine`, the pack's own rule: EJDict `cleanShort`, a definition `definitionLine`, a translation table its first word; the entry's own sense when it still has it, for its hint), an English definition in its cached translation (`translatedLine`; never translated here, so a sense the window has not translated stays English with `lineLang`), an AI meaning as it is
- Lists (M1b): `termSummaries` takes the list's `sourceUrl` and gives each saved term its `meanings` (lines, most chosen first, then the newest) and `chosen` (the sentences of that source with a meaning, and its key); the list matches a place's sentence (a video's card as saving records it, an article's sentence) to them. A choice in the window asks the term's summary again. `listTermsWithStats` gives each term its `meanings`. The store reads several terms' meanings at once (`meaningsOfTerms`)

## Interface language
- The extension `i18n` API follows the browser's language and cannot be chosen by the user, so use a small custom mechanism: every UI string goes through `t("key")` with one file per language (`locales/en.json`). Switch with the `uiLocale` setting, default `en`

## Browser differences (Firefox and others)
Only the Chrome version is published, but the structure must not need rewriting when other browsers follow.

### Principles
1. Call extension APIs through WXT's `browser` (`wxt/browser`). Never use `chrome.*` directly in code
2. Features that exist only in some browsers always sit behind a part (`TranslationProvider`, `PlatformAdapter`, …) and are **detected by whether the feature exists**, never by browser name or user agent
3. When a feature is missing, hide everything related to it (no grayed-out controls, no permanent "not available in this browser")
4. Strings containing a browser name come from `BrowserEnv`
5. WXT generates the manifest per browser. Firefox gets `browser_specific_settings.gecko.id`, and its background is an event page (`background.scripts`) instead of a service worker
6. Verify only that the Firefox build succeeds (no behavior guarantee, not published)

### What `BrowserEnv` holds
- Browser name and sync name (Chrome sync / Firefox Sync) for UI text
- Features detected where `BrowserEnv` is built (File System Access API). The translator is detected in the UI, where it runs: it never exists in the service worker. The built-in AI is detected by its provider (`chromePromptApi`), where it runs
- Add a field only when code reads it

## Chrome Web Store requirements (checked 2026-11-09)
No outright blocker. Decisions and requirements:
- **Subtitles (decided)**: keep YouTube and Netflix. Subtitle tracks are processed in memory; what is stored is the sentence in which a saved word appears (as an occurrence) and, while Sentence history is on, the lines that actually played (on the device only). Policy risk: "do not facilitate unauthorized access to content" / copyrighted content. Language Reactor does the same on the store. Prepare a written justification for review
- **Host access (decided)**: keep the content script on all sites (`<all_urls>`), accepting an in-depth review (can take weeks). Write a justification (article highlighting on any page the user reads)
- **Sentence history (decided)**: on by default, as in the mock. Browsing activity may be collected only for a user-facing feature described prominently in the store listing and in the UI, so the listing and Settings must describe it clearly, and it stays on the device
- **Privacy policy (required)**: any extension that handles user data needs a privacy policy URL, even when data stays on the device. Recorded sources (URL, title) and sentences count as user data. Disclose: what is stored locally, that word status goes through the browser's sync, that nothing is sent to the developer. Include the Limited Use compliance statement. Host it somewhere public without a server (e.g. GitHub Pages; this repo is private, so a separate public page is needed)
- **2026 policy update (in force since 2026-08-01)**: data collected must be necessary for the single purpose and prominently disclosed
- **Code**: no remotely hosted code (everything bundled, including the MAIN-world scripts); no obfuscation (minification is fine). Hooking page fetch/XHR/`JSON.parse` is not prohibited but needs a justification
- **Downloaded language data**: data, not code, so allowed. Packs are JSON read with `JSON.parse`, verified against hashes bundled with the extension. The privacy policy names the hosts (jsDelivr, unpkg), says they see the IP address and which packs were fetched, and that no page content or words are sent. No pack is bundled, so the policy and the listing say that the language data is downloaded right after install (English → Japanese about 9 MB) and that nothing works offline until it is; never that it works offline from install
- **On-device AI (phase 3)**: no network and no new permission. The privacy policy and the listing say that the sentence and the lines around it go to the browser's on-device model, on the device. The later API-key step sends them to a third party: its own consent, listing text and a look at the sites' terms
- **Single purpose**: "learn vocabulary on the videos and articles you read" — keep every feature framed around it
- **Listing**: icon, screenshots and a description are mandatory; no keyword lists ("YouTube Netflix …"); "works with YouTube and Netflix" wording only, no third-party logos
- **Account**: 2-Step Verification; trader / non-trader declaration (EU DSA) — the user decides before publishing
